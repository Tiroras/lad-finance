## Нулевая высота нижней панели на Android — 2 октября 2026 года

Пользователь уточнил, что на проблемных этапах не появляется само нижнее окно, а не только подсветка. В `Sheet` найдена несовместимость стилей с нативным Yoga: обёртка `TourFrame` задаёт `flex: 1`, а окно переопределяло только `flexGrow`, `flexShrink` и `flexBasis`. В `Node::processFlexBasis()` установленного React Native положительный `flex` сохраняет нулевой basis, даже когда `flexBasis` явно равен `auto`.

Ошибка воспроизведена отдельной C++-пробой, собранной с исходниками Yoga из установленного React Native. При экране 390 × 844, нижнем отступе 20 и ограничении высоты окна 820 прежнее сочетание давало высоту панели 20 и высоту её обёртки 0. После явного `flex: 0` у обёртки — 820 и 800 соответственно; содержимое прокрутки получает оставшуюся высоту. Результат повторён с настройками Yoga из RN (`YGErrataAll`, `FixFlexBasisFitContent`), при первом расчёте и после изменения высоты подсказки. Браузерный CSS этот конфликт обрабатывает иначе, поэтому прежние успешные веб-тесты не выявляли схлопывание.

Исправление ограничено стилем `TourFrame` внутри `Sheet`: добавлен `flex: 0`. Основной экран, анимация окна, прокрутка и порядок шагов не менялись. На телефоне проверка не выполнялась по просьбе пользователя; нативная проба подтверждает ошибку расчёта высоты и её исправление, но не проверяет все причины восстановления интерфейса после касания.

Реестр хранит ID и названия дополнительных профилей отдельно от финансового JSON; повреждение реестра останавливает загрузку без его перезаписи. Имена проверяются на длину, управляющие символы и повторы. Копии содержат только один учёт; обычный импорт и очистка затрагивают только текущий профиль, сохраняя его ID, название и тип. Без опции демокопии по-прежнему отклоняются.

Переключение сначала завершает сохранение текущего профиля. Если оно не удалось или выбранный профиль повреждён, текущий учёт остаётся открыт, выбранные данные не заменяются. При ошибке чтения другого профиля можно восстановить именно его копию с явным названием назначения и подтверждением; открытый здоровый учёт сохраняется. При повреждении активного профиля на запуске доступно открытие другого профиля без перезаписи повреждённых данных. Финансовое восстановление не предлагается при ошибке чтения реестра. Каждая запись очереди содержит свой профиль; запоздавшие обработчики другого профиля не могут менять текущий учёт. Формы закрываются при переключении, валютные запросы отменяются. Уведомления планируются для активного профиля; их идентификаторы и содержимое включают его ID. Старые и чужие уведомления не открывают платёж другого профиля даже при совпадении ID.

В SDK 57 значение публичной переменной встраивается в код при преобразовании. Теперь `metro.config.js` разделяет кэш по режимам. Регрессионный браузерный тест последовательно экспортирует и открывает готовые Web-пакеты без опции, с `true` и снова без опции, не очищая кэш; проверяет данные, доступность примеров и открытие мастера.

## Сохранение в Expo Go на Android — 26 сентября 2026 года

Ошибка сохранения воспроизведена на чистом Android-эмуляторе API 36.1 с Expo Go 57.0.9. Причина установлена в нативном адаптере: после шифрования хранилище проверяет обратное расшифрование, передавая строку base64 в `AESSealedData.fromCombined`. Публичные типы Expo Crypto разрешают строку, но Android-реализация установленного SDK 57 принимает только `ByteArray`. Нативный вызов отклонял аргумент с `ERR_UNEXPECTED` ещё до записи конверта в AsyncStorage. Повторное сохранение упиралось в тот же вызов. Диагностика выводила только имя вызова, тип аргумента и код ошибки, без ключей и содержимого учёта; временная диагностика удалена.

Адаптер теперь декодирует base64 в `Uint8Array` перед вызовом Expo Crypto. Формат конверта, ключ в SecureStore, AES-256-GCM, AAD и проверка записи сохранены. Миграция формата не требуется. Новый тест исполняет сам нативный адаптер с изолированными платформенными модулями и настоящим AES-GCM Node.js; граница `fromCombined` воспроизводит требование Android к массиву байтов. До исправления тест падал, после него проверяет сохранение и повторное чтение Unicode, свежий IV, миграцию старой открытой записи и отказ при повреждении тега без перезаписи данных.

После исправления в Expo Go исчез баннер ошибки. Через нативную форму записан тестовый расход 17 ₽; после полной остановки процесса и повторного запуска запись прочитана из хранилища. Проверены её сумма, отсутствие дубля, число операций, общий остаток счетов и итог расходов за месяц. Просмотрен снимок истории после перезапуска. Прошли TypeScript, весь набор модульных тестов, Playwright для основных операций и переноса данных, проверка зависимостей по локальным сведениям SDK и экспорт Android/iOS/Web. Физическое устройство и iOS в этой проверке не использовались.
