# Перенос данных

| Формат            | Что содержит                                                                   | Где открыть                                                      |
| ----------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| Универсальный CSV | Операции выбранных счетов и периода, категории, заметки, обе стороны переводов | Таблицы и финансовые приложения с сопоставлением столбцов        |
| CSV для YNAB      | Операции одного счёта с отдельными приходом/расходом                           | Файловый импорт YNAB; категории назначаются после импорта        |
| JSON              | Весь учёт, категории, планы, цели, настройки прогноза и сохранённые сценарии   | Восстановление Лада, собственные инструменты обработки JSON      |
| `.ladbackup`      | Полный обычный снимок или большой архив, зашифрованные отдельным паролем       | Лад на другом устройстве или после переустановки                 |
| `.ladrescue`      | Большой архив: проверенный исходник и актуальный снимок, без шифрования        | Лад с поддержкой архива версии 2; восстановление в новый профиль |

CSV, JSON и `.ladrescue` открытые. Пароль защищённой копии не нужен для обычного CSV-экспорта из разблокированного приложения. Форматы и настройки защиты устройства разделены.

## CSV

Откройте **Операции → Экспортировать операции в CSV** либо **Профиль → Данные и копии → Экспортировать операции в CSV**. Выберите формат, счёт и необязательный период. Обе границы периода включаются; пустая начальная дата означает всю историю. Форма показывает число исходных операций, строк и файлов перед сохранением. Набор создаётся локально, в UTF-8 с BOM, разделителем-запятой, CRLF и экранированием кавычек/переносов строк.

Универсальные столбцы:

| Столбец                                 | Значение                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------ |
| Date                                    | Локальная дата `YYYY-MM-DD`                                                          |
| Type                                    | `income`, `expense`, `transfer`                                                      |
| Amount                                  | Сумма в валюте счёта: точка, 0/2/3 десятичных знака по валюте, без разделителя тысяч |
| Currency                                | ISO-код валюты Amount, например `RUB`, `USD`, `JPY`                                  |
| Description                             | Название операции                                                                    |
| Category                                | Основная категория либо `Основная / Подкатегория` для расходов                       |
| Account / ToAccount                     | Счёт экспорта (при всех счетах — исходный) и целевой счёт                            |
| Note                                    | Заметка                                                                              |
| ID                                      | Уникальный ID строки операции или её части                                           |
| FromAmount / FromCurrency / FromAccount | Исходные сумма, валюта и счёт перевода                                               |
| ToAmount / ToCurrency                   | Фактически полученная сумма и валюта перевода                                        |

Разделённая покупка экспортируется только строками частей, без дополнительной строки полной суммы. `GroupID` связывает части, `RefundOf` указывает исходную покупку. Возврат содержит положительные строки по категориям покупки; в YNAB связи поясняются в Memo. Движения долга передаются фактическими суммами с пояснениями в заметках. Принимающее приложение может не восстановить смысл связей автоматически. Полный JSON и `.ladbackup` сохраняют части, возвраты, долги, условия кредитных карт, сверки, историю бюджетов, правила, шаблоны и профили CSV.

Доход положительный, расход отрицательный. При экспорте всех счетов перевод представлен **одной** строкой типа `transfer`, с отрицательной суммой со стороны отправителя и двумя счетами. Его нельзя суммировать как расход. При выборе одного счёта перевод положителен для получателя и отрицателен для отправителя. После импорта проверьте, как принимающее приложение учитывает переводы, чтобы не продублировать их.

CSV для YNAB: `Date,Payee,Memo,Outflow,Inflow`, один счёт на файл, суммы в его валюте. Для полученного валютного перевода используется фактическая сумма зачисления. Валюта принимающего счёта должна совпадать. В `Memo` помещается путь категории либо пояснение перевода и заметка. Автоматический перенос категорий и связывание внутренних переводов не обещаются: проверьте их в принимающем приложении. Заголовки сверены с [официальным руководством YNAB](https://support.ynab.com/en_us/file-based-import-a-guide-Bkj4Sszyo); импорт в реальный аккаунт YNAB в ходе разработки не выполнялся.

Текст, который таблицы могут принять за формулу (`=`, `+`, `-`, `@` в начале, включая пробелы и управляющие символы), получает ведущий апостроф. Числовые суммы остаются числами. Некоторые приложения могут показать этот апостроф как часть названия — это осознанная защита при открытии CSV в таблицах.

CSV не переносит начальные остатки, корректировки сверки, бюджеты, цели, параметры долгов или сценарии. Для полного переноса между установками Лада используйте копию. Экспорт до 20 000 исходных операций автоматически разбивается на части: в каждой не более **5000 логических строк данных** и **2 000 000 UTF-8 байт**, включая BOM, заголовок и CRLF. Перенос строки внутри кавычек не является новой строкой данных. Все строки одной разделённой покупки или одного возврата сохраняются в одной части; покупка и её возврат могут оказаться в разных файлах. Количество частей зависит от итоговых строк и байтов, а не только от числа операций. Слишком большая неделимая группа или ячейка вне ограничений импортёра прекращает подготовку всего набора с объяснением; часть истории молча не отбрасывается.

**«Сохранить CSV»** фиксирует текущие профиль, снимок учёта, дату и фильтры, подготавливает все части и передаёт первую. Имена содержат общий ID набора и номера частей. Остальные файлы передаются кнопками **«Сохранить часть N»**; **«Повторить передачу части N»** использует те же байты и имя. Изменение фильтров либо **«Подготовить новый набор»** создаёт новый набор с новыми отметками. Старый результат не объявляется выгрузкой изменившихся данных.

Каждая часть имеет отдельные даты подготовки, передачи, ручного подтверждения и проверки чтением. Скачивание браузером или возврат из системного меню означает только запрос передачи: результат внешнего сохранения неизвестен. Ошибка передачи тоже не подтверждает файл. После проверки его наличия нажмите **«Я сохранил часть N»**; **«Часть N: ещё нет»** оставляет сохранение неподтверждённым. **«Проверить файл части N»** сравнивает размер и SHA-256 выбранных байтов с нужной частью без изменения учёта. Другой читаемый CSV, даже с похожими строками, не подтверждает эту часть. Счётчики «Подтверждено вами» и «Проверено чтением» охватывают весь набор: подтверждение последнего файла не подтверждает остальные.

Подготовленные байты существуют только пока открыто окно. После его закрытия сохраняются отметки последнего набора этого профиля: ID, нейтральные имена файлов, размеры, хеши и даты, без строк CSV. Можно проверить ранее сохранённые файлы; для новой передачи потребуется новая подготовка. Эти отметки не входят в финансовую копию и не гарантируют будущую доступность внешнего файла.

Части импортируются **по одному файлу** через обычный мастер. Каждый файл проверяется и применяется атомарно, но набора общей транзакции нет: отмена или ошибка следующего файла сохраняет уже принятые части. Повторы, категории и переводы проверяются заново; сводка относится к одному импорту. [Правила импорта](CSV_IMPORT.md#результат-импорта-и-повтор-сохранения).

## Полные копии

Откройте **Профиль → Данные и копии**. **«Экспортировать резервную копию»** создаёт открытый JSON, а для большого восстановленного учёта — открытый `.ladrescue`. **«Создать копию с паролем»** открывает ввод и повтор пароля (10–256 символов), затем **«Сохранить защищённую копию»** создаёт `.ladbackup`. Пробелы и регистр пароля значимы. Пароль не сохраняется и не восстанавливается; храните его отдельно от файла.

Копия содержит финансовые данные только открытого профиля: счета, операции, категории, бюджеты, цели, долги, планы доходов и платежей, курсы и сценарии. «Личный», дополнительные профили и демо экспортируются отдельно; общего архива всех профилей нет. Список профилей, их названия и выбранный профиль в файл не входят. Обычная замена затронет только явно выбранный профиль, сохраняя его ID, название и тип. Отдельное действие **«Восстановить в новый профиль»** создаёт личный профиль с новым ID; существующие записи остаются на месте. Название профиля хранится без шифрования, поэтому лучше использовать нейтральное имя. При выключенной опции демо копии с признаком демонстрационного учёта не принимаются.

Перед подготовкой приложение пытается подтвердить сохранение текущего состояния. Если это не удалось, но прежний снимок читается, появляется отдельное подтверждение **«Экспортировать последний сохранённый снимок?»**. В такой файл не входят более новые несохранённые изменения; интерфейс сохраняет это предупреждение рядом с отметкой копии. Отмена не удаляет изменения в памяти и не повторяет финансовое действие. Если нет читаемого снимка, приложение сообщает об ошибке вместо подстановки пустых данных.

На телефоне открывается системное меню сохранения/передачи, в браузере — скачивание. В разделе «Данные и копии» отдельно показаны три факта:

1. **Подготовлена** — файл сформирован; это не подтверждает его сохранение за пределами приложения. Отмена Sharesheet не превращает подготовку в сохранение.
2. **Сохранение подтверждено вами** — вы нажали **«Я сохранил файл»**, проверив его наличие в выбранном месте.
3. **Проверена чтением** — вы выбрали файл через **«Проверить копию»**, приложение успешно прочитало/расшифровало его, проверило финансовую модель и совпадение с последним подготовленным файлом этого профиля.

Пока окно открыто, **«Повторить передачу этой копии»** отправляет тот же подготовленный файл, включая уже зашифрованные байты, без повторного ввода пароля или нового шифрования. Пароль после подготовки очищается. Кнопки создания подготавливают новую копию из актуального учёта; после закрытия окна прежние байты не хранятся, хотя отметка последнего файла остаётся. Ошибка передачи допускает повтор, но не подтверждает сохранение.

Проверка чтением не заменяет учёт. Для последней копии сверяются размер и SHA-256 всех точных байтов файла, а не имя или похожие суммы. Другой исправный файл можно прочитать, но он не получает отметку последнего экспорта. Новое шифрование тех же данных создаёт другой файл из-за новой соли и nonce. После успешного чтения доступно отдельное пробное восстановление в новый профиль с подтверждением. Эти локальные отметки не входят в финансовую копию; прежняя отметка даты означает только подготовку. Спустя месяц после подготовки появляется напоминание.

**«Восстановить из файла»** принимает JSON, `.ladbackup` и `.ladrescue`. Защищённый файл сначала требует пароль; затем показывается проверенное содержимое. Для обычной копии есть отдельное подтверждение замены, для большого архива — восстановление только в новый профиль. Неверный пароль, повреждённый файл и отмена предпросмотра ничего не меняют. Тот же выбор копии доступен при ошибке чтения хранилища, без ключа исходного устройства. Перед заменой сохраните текущие данные, если они нужны.

После применения открывается **«Результат импорта»**: профиль, проверенный формат, режим «Замена учёта» или «Новый профиль», время, состав и остатки по каждому счёту в его валюте. Для замены показывается прежний состав, если он был доступен; при повреждённом хранилище неизвестные данные не подменяются нулём. Статус **«Импорт сохранён и проверен чтением»** появляется после подтверждения точного снимка в хранилище. Создание нового профиля записывает сводку уже подтверждённого восстановления без повторного финансового сохранения.

История открывается через **Профиль → Данные и копии → Результаты импорта** и существует только до закрытия или перезапуска приложения. Сводки сохраняются при закрытии окна и смене профиля, но не являются текущими остатками. Открытие результата не повторяет импорт. При неподтверждённой записи доступны повтор сохранения той же копии и отдельно подтверждаемое чтение снимка устройства; поведение и ограничения описаны в [результате импорта](CSV_IMPORT.md#результат-импорта-и-повтор-сохранения).

Если другой профиль не открывается, раздел **«Профили»** предлагает восстановить его из копии. В подтверждении указано название заменяемого профиля; здоровый открытый учёт не меняется. При ошибке запуска также можно открыть другой профиль, сохранив повреждённые записи.

Если повреждён сам список профилей, **«Проверить сохранённые профили»** ищет их существующие записи без изменения или удаления. Результат различает читаемый, пока недоступный, повреждённый и отсутствующий снимок. Выбор и подтверждение восстанавливают служебный список, сохраняя финансовые данные и ключи. Можно также выбрать внешнюю копию для нового профиля. Прерванная операция продолжается с тем же ID; повтор не создаёт новый дубликат. **«Вернуть прежний список профилей»** возвращает только прежние метаданные, сохраняя уже записанные снимки. Старые общие пространства до появления профилей этим поиском не переносятся.

Финансовая схема поддерживает версию **9** для самостоятельного вывода из цели. Версия 8 используется для назначений счетов и плановых переводов прогноза, оснований исторических оценок, активности условий сценария и счёта разового события. Версия 7 хранит индивидуальные графики целей, годовые фонды и актуальность кредитных условий; версия 6 — историю условий платежей, доходов и бюджетов и изменения отдельных поступлений; версия 5 — архив счетов и статусы операций. Чтение копий 1–4 сохраняет прежнюю нормализацию в 4; версии 5–8 читаются без новых полей. Формат повышается действием с новой семантикой, а не открытием копии; последующие действия его не понижают. Прежние нормализация и контрольные суммы сохраняются.

Записи без кода валюты считаются рублёвыми; валюты и оценки версии 3 сохраняются. Полная копия включает валюты, курсы, ручные корректировки, оценки и все статусы операций, включая ожидания и отмены, а также архивные счета. Начиная с формата 6 сохраняются интервалы условий платежей, доходов и бюджетов, исходные ключи связанных событий, паузы и переносы/отмены поступлений. Формат 7 добавляет версии суммы, графика и срока цели, ссылки взносов на версию и исходную дату, циклы фондов и отдельные освобождения распределения со ссылками на реальные переводы и полный расход. Даты подтверждения выписки и напоминания о следующем обновлении сохраняются вместе с ранее учтёнными погашениями карты.

Формат 8 дополнительно сохраняет повседневный счёт ежедневных расходов, пары счетов взносов, источники погашения и плановые переводы с двумя суммами при обмене; у операции — дату и источник оценки; у строк сценария — необязательный признак участия, у разового события — необязательный счёт. В старой записи отсутствие основания означает «неизвестно», отсутствие признака участия — включённую строку. Эти значения используются при расчёте без дописывания полей при чтении. Копия сценария сохраняет отдельные ID сценария и его разовых событий.

Формат 9 разрешает запись `goalReleases` без `cycleId` для самостоятельного вывода. Она хранит цель, дату, сумму в валюте цели и ID фактического перевода; формат повышается при первом выводе. При исправлении или удалении такого перевода освобождение меняется вместе с ним. Создание, изменение и копирование сценария после вывода сохраняют формат 9 и связи освобождения, поэтому последующая полная копия остаётся читаемой. Связи годовых фондов сохраняют обязательный цикл. Копии версий 7–8 с освобождением без цикла отклоняются, прежние корректные копии читаются без добавления полей.

Проверка отклоняет пересечения действующих интервалов версий, неверные ссылки, повторяющиеся события, несогласованный цикл фонда и некорректные назначения счетов до замены учёта. Поля формата 8 в копии, объявленной версией 1–7, отклоняются до удаления неизвестных полей. Неизвестные обязательства прежних выключенных планов не создаются; у старой цели остаются прежний месячный взнос и общий день, у старой карты дата подтверждения остаётся неизвестной. CSV переносит фактические движения, но не восстанавливает эти внутренние связи, назначения прогноза и основания оценок. Версии шифрованных конвертов и большого архива независимы от финансовой схемы.

Черновики форм в неё не входят. CSV экспортирует только проведённые операции; для полного переноса используйте JSON или защищённую копию. Старое приложение может не принять новую версию — обновите его перед восстановлением. Обычный новый JSON ограничен 5 МБ UTF-8, защищённый JSON-конверт версии 1 с накладными данными — около 10 МБ. Эти пределы не увеличены.

JSON сохраняется компактно, без отступов. Новые обычные локальные снимки ограничены 5 МБ UTF-8; превышающее размер изменение отклоняется до замены текущего учёта. Для допустимой старой копии, которая больше этого предела или выросла при нормализации, предусмотрен полный большой архив версии 2. Он содержит ограниченный проверенный исходник и актуальный снимок, включая изменения после восстановления. Архив не разбивается на файлы; CSV не заменяет этот маршрут.

В **Профиль → Данные и копии** начиная с 80% объёмного предела появляются предупреждения: число операций и других записей, календарь платежей и размер текущего финансового JSON в байтах UTF-8. Архивные записи тоже занимают место; кириллица и эмодзи могут занимать несколько байтов на символ. Сообщение показывает использованное и предельное значения и способ исправления: сохранить копию, сократить заметки, удалить ненужный план либо продолжить новую историю в отдельном профиле. Порог 80% выбран для предупреждения и не свидетельствует о быстродействии. Пределы 20 000 операций, 5 000 000 байт обычного JSON и остальные защитные ограничения не повышены.

Восстановление большого архива создаёт новый профиль. Допуск вычисляется из проверенного исходника с зафиксированной датой и версией нормализации; произвольное число внутри файла не разрешает больший учёт. Исходник ограничен 5 000 000 единиц UTF-16 и 15 000 000 байт UTF-8. Текущий снимок проверяется отдельно и может превышать обычный лимит только в пределах вычисленного допуска. Пока он больше 5 МБ, сохранение должно уменьшать размер; можно удалять ненужные операции или сокращать заметки. После достижения обычного предела исключение больше не разрешает рост сверх него. Повторная полная копия сохраняет актуальные записи, а не возвращает учёт к исходному архиву.

Большой архив без пароля имеет расширение `.ladrescue` и содержит открытые данные. Защищённый вариант имеет расширение `.ladbackup`, но использует новый бинарный формат версии 2 вместо обычного JSON-конверта версии 1. Для него требуется обновлённый Лад; прежние обычные копии продолжают читаться. Точные поля и порядок безопасного чтения описаны в [документе о защите](SECURITY.md#большой-архив-версии-2).

Ключ Keychain/Keystore, настройка блокировки, пароль и разрешения уведомлений в копии отсутствуют. На новом устройстве защиту и системные разрешения настраивают отдельно. [Алгоритм защиты, формат конверта и ограничения](SECURITY.md).
