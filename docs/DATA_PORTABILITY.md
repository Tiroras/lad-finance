# Перенос данных

| Формат            | Что содержит                                                                   | Где открыть                                                 |
| ----------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| Универсальный CSV | Операции выбранных счетов и периода, категории, заметки, обе стороны переводов | Таблицы и финансовые приложения с сопоставлением столбцов   |
| CSV для YNAB      | Операции одного счёта с отдельными приходом/расходом                           | Файловый импорт YNAB; категории назначаются после импорта   |
| JSON              | Весь учёт, категории, планы, цели, настройки прогноза и сохранённые сценарии   | Восстановление Лада, собственные инструменты обработки JSON |
| `.ladbackup`      | То же содержимое, зашифрованное отдельным паролем                              | Лад на другом устройстве или после переустановки            |

CSV и JSON открытые. Пароль защищённой копии не нужен для обычного CSV-экспорта из разблокированного приложения. Форматы и настройки защиты устройства разделены.

## CSV

Откройте **Операции → Экспортировать операции в CSV** либо профиль. Выберите формат, счёт и необязательный период. Обе границы периода включаются; пустая начальная дата означает всю историю. Форма показывает число исходных операций и строк экспорта перед сохранением. Файл создаётся локально, в UTF-8 с BOM, разделителем-запятой, CRLF и экранированием кавычек/переносов строк.

Универсальные столбцы:

| Столбец                                 | Значение                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------ |
| Date                                    | Локальная дата `YYYY-MM-DD`                                                          |
| Type                                    | `income`, `expense`, `transfer`                                                      |
| Amount                                  | Сумма в валюте счёта: точка, 0/2/3 десятичных знака по валюте, без разделителя тысяч |
| Currency                                | ISO-код валюты Amount, например `RUB`, `USD`, `JPY`                                  |
| Description                             | Название операции                                                                    |
| Category                                | Основная категория либо `Основная / Подкатегория` для расходов                       |
| Account / ToAccount                     | Счёт экспорта (при всех счетах — исходный) и целевой счёт                            |
| Note                                    | Заметка                                                                              |
| ID                                      | Уникальный ID строки операции или её части                                           |
| FromAmount / FromCurrency / FromAccount | Исходные сумма, валюта и счёт перевода                                               |
| ToAmount / ToCurrency                   | Фактически полученная сумма и валюта перевода                                        |

Разделённая покупка экспортируется только строками частей, без дополнительной строки полной суммы. `GroupID` связывает части, `RefundOf` указывает исходную покупку. Возврат содержит положительные строки по категориям покупки; в YNAB связи поясняются в Memo. Движения долга передаются фактическими суммами с пояснениями в заметках. Принимающее приложение может не восстановить смысл связей автоматически. Полный JSON и `.ladbackup` сохраняют части, возвраты, долги, условия кредитных карт, сверки, историю бюджетов, правила, шаблоны и профили CSV.

Доход положительный, расход отрицательный. При экспорте всех счетов перевод представлен **одной** строкой типа `transfer`, с отрицательной суммой со стороны отправителя и двумя счетами. Его нельзя суммировать как расход. При выборе одного счёта перевод положителен для получателя и отрицателен для отправителя. После импорта проверьте, как принимающее приложение учитывает переводы, чтобы не продублировать их.

CSV для YNAB: `Date,Payee,Memo,Outflow,Inflow`, один счёт на файл, суммы в его валюте. Для полученного валютного перевода используется фактическая сумма зачисления. Валюта принимающего счёта должна совпадать. В `Memo` помещается путь категории либо пояснение перевода и заметка. Автоматический перенос категорий и связывание внутренних переводов не обещаются: проверьте их в принимающем приложении. Заголовки сверены с [официальным руководством YNAB](https://support.ynab.com/en_us/file-based-import-a-guide-Bkj4Sszyo); импорт в реальный аккаунт YNAB в ходе разработки не выполнялся.

Текст, который таблицы могут принять за формулу (`=`, `+`, `-`, `@` в начале, включая пробелы и управляющие символы), получает ведущий апостроф. Числовые суммы остаются числами. Некоторые приложения могут показать этот апостроф как часть названия — это осознанная защита при открытии CSV в таблицах.

CSV не переносит начальные остатки, корректировки сверки, бюджеты, цели, параметры долгов или сценарии. Для полного переноса между установками Лада используйте копию. Импорт CSV Лада ограничен 5000 строками за раз; экспорт может содержать всю историю до 20 000 операций. Большой CSV при обратном импорте нужно разделить по периодам. Повторы, категории и переводы проверяются в мастере импорта.

## Полные копии

В профиле **«Экспортировать резервную копию»** создаёт открытый JSON. **«Создать копию с паролем»** открывает ввод и повтор пароля (10–256 символов), затем **«Сохранить защищённую копию»** создаёт `.ladbackup`. Пробелы и регистр пароля значимы. Пароль не сохраняется и не восстанавливается; храните его отдельно от файла.

На телефоне открывается системное меню сохранения/передачи, в браузере — скачивание. В профиле записывается дата последней _подготовленной_ копии; она не подтверждает, что файл действительно сохранён после системного меню. Спустя месяц появляется напоминание в профиле. Это локальная отметка устройства, она не входит в финансовую копию.

**«Восстановить из файла»** принимает JSON и `.ladbackup`. Защищённый файл сначала требует пароль; затем показывается проверенное содержимое и отдельная кнопка замены текущих данных. Неверный пароль или повреждённый файл ничего не меняет. Тот же путь доступен при ошибке чтения хранилища, без ключа исходного устройства. Перед заменой сохраните текущие данные, если они нужны.

Финансовая схема — версия 4; копии версий 1, 2 и 3 читаются с миграцией. Записи без кода валюты считаются рублёвыми; валюты и оценки версии 3 сохраняются. Полная копия включает валюты, курсы, ручные корректировки и оценки операций. Старое приложение может не принять новую версию — обновите его перед восстановлением. Максимум открытого UTF-8 содержимого — 5 МБ; защищённый hex-конверт с накладными данными — около 10 МБ. Превышение размера отклоняется перед экспортом, чтобы не создать файл, который нельзя восстановить.

Ключ Keychain/Keystore, настройка блокировки, пароль и разрешения уведомлений в копии отсутствуют. На новом устройстве защиту и системные разрешения настраивают отдельно. [Алгоритм защиты, формат конверта и ограничения](SECURITY.md).
