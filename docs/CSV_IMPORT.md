# Импорт банковской выписки

В профиле откройте **«Данные и копии» → «Импортировать банковский CSV»**. Файл обрабатывается на устройстве; сервер и банковские пароли не нужны. Форматы конкретных банков не объявляются сертифицированными: мастер позволяет сопоставить их колонки вручную.

1. Выберите CSV/TSV до 2 000 000 байт, не более 5000 логических строк данных и 50 колонок. Поддерживаются UTF-8 с BOM и без, Windows-1251, разделители `;`, `,` и табуляция. Можно указать строку заголовков после преамбулы банка.
2. Выберите повседневный счёт. Начальный остаток должен отражать баланс **до** импортируемой истории. Предпросмотр показывает, как изменится рассчитанный остаток; приложение не подменяет начальный остаток автоматически.
3. Сопоставьте дату, описание и сумму. Для одной суммы задайте значение положительного знака; для раздельных колонок — приход и расход. При наличии выберите валюту, статус, категорию, тип и ID банка.
4. Проверьте строки. Можно снять выбор, уточнить тип и категорию, указать второй свой счёт для перевода. Ошибки и повторы не импортируются.
5. Нажмите «Импортировать … операций». Существующие операции сохраняются, выбранные добавляются одним обновлением. Затем открывается результат применения и проверки записи; одного завершения предпросмотра недостаточно для подтверждения сохранения.

Даты: `YYYY-MM-DD`, `DD.MM.YYYY`, варианты со временем; для `/` явно выбирается порядок дня и месяца. Дата должна быть от 2000 года и не позднее сегодняшней. Суммы — в валюте выбранного счёта: JPY без дробной части, KWD до трёх, остальные поддерживаемые валюты до двух десятичных знаков; пробелы между тысячами допустимы, запятые и точки используются только как десятичный разделитель. Несовпадение валюты строки со счётом и неподтверждённые статусы отклоняются. Если колонка валюты отсутствует, используется валюта выбранного счёта. Для валютного перевода укажите фактическую сумму на втором счёте; без неё строка не импортируется. Оценка для статистики фиксируется по курсу на момент импорта, её можно исправить в форме операции.

Повторы с ID сверяются по счёту и ID банка. Без ID используется количество совпадений по счёту, второму счёту перевода, дате, типу, обеим суммам перевода и нормализованному описанию. Совпадения с вручную добавленными записями тоже пропускаются. Разные суммы под одним ID отклоняются. Одинаковые строки внутри файла без ID считаются отдельными операциями: проверьте их вручную. В выписках с изменившимися описаниями или разным набором одинаковых операций автоматическое сопоставление без ID может быть неоднозначным.

Потенциальный перевод не превращается автоматически в расход. Подтвердите его назначение в строке: перевод другому человеку может быть расходом, между своими счетами — переводом. Перевод из накоплений на повседневный счёт разрешён только в пределах свободных денег, не закреплённых за целями.

Ручной ввод и CSV соблюдают одни финансовые ограничения. Перед добавлением выбранный пакет проверяется заново по актуальному учёту; ошибка общей проверки оставляет весь учёт без изменений. Большие пакеты обычных доходов и расходов проверяются совместно, без повторной проверки всей истории для каждой строки. Переводы и связанные записи сохраняют последовательную проверку по датам.

Оплаченный из выписки регулярный платёж можно связать с расходом в календаре, не создавая второй расход. Полученный доход можно связать с планом дохода в разделе «Прогноз», чтобы он повторно не прибавлялся к будущему остатку.

[Пример с рублёвыми операциями](examples/statement.csv). CSV-формулы остаются обычным текстом и не исполняются. Временная нативная копия выбранного файла удаляется после чтения, в том числе при ошибке проверки.

Категория может быть пользовательской: полное имя подкатегории записывается как «Дом / Ремонт». Архивные категории исключены из автоматического выбора; неоднозначные названия требуют ручного выбора в предпросмотре. Для обратного переноса доступен [экспорт CSV](DATA_PORTABILITY.md).

## Результат импорта и повтор сохранения

В результате показаны профиль, формат, режим **«Добавление операций»**, время начала и подтверждения, прежний и новый состав учёта, остатки по каждому счёту в его валюте. Для CSV отдельно указаны число строк данных, добавленных операций и пропуски: ошибки, повторы, строки, исключённые пользователем. Группы пропусков не пересекаются; счётчики рассчитаны при применении к актуальному учёту, а не только при первом предпросмотре. Сводка относится к одному файлу и моменту операции.

**«Импорт сохранён и проверен чтением»** означает, что хранилище вернуло точный применённый снимок этого профиля. При ошибке после применения показывается **«Изменения применены в памяти, запись на устройстве не подтверждена»**. Состояние не откатывается молча и пакет повторно не добавляется. Пока запись не подтверждена, финансовые изменения, смена профиля, новый импорт и сброс приостановлены. Окно можно закрыть и открыть снова через баннер неподтверждённого импорта.

**«Повторить сохранение импорта»** сначала проверяет сохранённую копию, а при необходимости записывает тот же снимок с прежними ID. Это не повтор финансового действия. Если первая попытка фактически записала данные, но не получила подтверждение, точное повторное чтение может завершить её без новой записи.

Дополнительное действие **«Открыть сохранённый снимок устройства»** требует явного подтверждения. Приложение читает сохранённое состояние и заменяет им только память; этот шаг не записывает и не удаляет финансовые данные на устройстве. Снимок может отличаться от импортированной копии; его состав показан отдельно. Если прочитать корректный снимок не удалось, текущая память и незавершённый результат сохраняются.

При восстановлении повреждённого хранилища сообщение другое: **«Запись копии не подтверждена. Учёт в памяти ещё не заменён…»**. Результат и повтор доступны прямо на экране загрузки; состав до восстановления обозначен неизвестным. Подтверждение записи предшествует открытию восстановленного учёта.

Все сводки доступны через **Профиль → Данные и копии → Результаты импорта → Результаты этого запуска**. Они переживают закрытие окна и переключение профиля, но не перезапуск приложения; финансовое содержимое сводок не сохраняется в служебные отметки. Повторное открытие результата не выполняет импорт заново.

CSV-набор экспортируется [принимаемыми частями](DATA_PORTABILITY.md#csv), но импорт каждой части — отдельная операция. Уже принятые части остаются при отмене или ошибке следующей. Повторный выбор файла вновь проходит поиск дублей; автоматического объединения CSV-файлов, слияния полных JSON-копий и выборочного импорта JSON нет. Полная копия заменяет профиль после подтверждения либо восстанавливается в новый профиль.

## Профили источников и правила

В мастере можно сохранить название профиля, сопоставление колонок, кодировку, строку заголовков, порядок дня/месяца, счёт и валюту. Профиль применяется вручную; заголовки нового файла должны совпасть полностью и в том же порядке. Несовместимый профиль не применяется молча. Предпросмотр и проверка повторов выполняются при каждом импорте.

Пользовательские правила предлагают категорию по названию и показывают причину. Явно исправленная строка сохраняет выбранную категорию. Управление приоритетами и выключение правил — в профиле приложения. Старые операции автоматически не меняются.

CSV не восстанавливает внутренние связи частей, возвратов и долгов при обратном импорте; для полного переноса используется JSON или `.ladbackup`.

Ожидающие и отменённые операции не экспортируются в CSV и не считаются проведёнными повторами при импорте банковской истории. Совпадение importKey с незавершённой записью требует явного разрешения: импорт не создаёт второе движение молча. Архивные счета остаются доступны для просмотра/экспорта истории, но импорт новых операций выбирает активный счёт. Полные статусы и архив сохраняются финансовым JSON версий 5 и 6; версия 6 также сохраняет историю условий планов и исходные связи событий. Черновики форм в финансовую копию не входят.
