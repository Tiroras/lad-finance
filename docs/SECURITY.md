# Защита данных Лада

## Нативное хранилище

На iOS и Android записи шифруются AES-256-GCM через Expo Crypto. Каждое сохранение использует новый случайный IV; GCM проверяет целостность шифротекста, а дополнительные аутентифицированные данные связывают его с форматом и ID ключа. В AsyncStorage по ключу `lad-finance-encrypted-v1` хранится JSON-конверт с версией, ID ключа и base64 от IV, шифротекста и тега.

Случайный ключ хранится отдельно через Expo SecureStore: iOS Keychain с `WHEN_UNLOCKED_THIS_DEVICE_ONLY`, Android Keystore. Ключ не входит в экспорт. Данные и ключ могут находиться в памяти работающего приложения; блокировка интерфейса не обещает защиты от взломанной ОС, инструментирования процесса или доступа к памяти.

После чтения старого `lad-finance-v1` приложение валидирует данные, создаёт зашифрованную запись, проверяет расшифрование и чтение сохранённого конверта, затем удаляет старую незашифрованную запись. При наличии зашифрованного конверта повреждение или отсутствие ключа вызывает ошибку: автоматического возврата к старой открытой копии нет. Ошибка удаления старой копии также отображается, и удаление повторяется при следующем чтении/сохранении. Существующие внешние резервные копии эта миграция не изменяет.

## Блокировка

В профиле можно включить блокировку Face ID / Touch ID / Android-биометрией с допустимым системным кодом устройства. На Android запрашивается сильная биометрия. Включение и выключение требуют системной проверки. Настройка хранится отдельно от финансового JSON и не меняется при импорте или сбросе демоданных.

При запуске данные не загружаются до первого подтверждённого входа, если блокировка включена. При потере активности содержимое скрывается и вход закрывается. Системный диалог аутентификации не запускает блокировку повторно; отмена или уход в фон во время проверки не открывает приложение. Черновик открытой формы сохраняется под блокирующим экраном. iOS использует системную защиту предпросмотра приложения, Android — `FLAG_SECURE` через Expo ScreenCapture, включая запрет скриншотов при включённой блокировке.

Блокировка — проверка доступа к интерфейсу. Ключ шифрования не привязан к текущему набору биометрии (`requireAuthentication` для ключа не используется), поэтому добавление отпечатка не инвалидирует его автоматически. Надёжность кода и биометрии определяется настройками устройства. Face ID не работает в Expo Go: требуется собственная нативная сборка.

## Копии и восстановление

Экспортируемый JSON **не зашифрован**. Он предназначен для переноса и аварийного восстановления; храните его в защищённом месте. Временная копия экспорта удаляется после завершения системного меню обмена. Кэш импортируемых файлов удаляется после чтения и при ошибках валидации.

При потере ключа или повреждении данных экран ошибки позволяет выбрать JSON-копию, проверить её и отдельно подтвердить замену хранилища. Восстановление создаёт ключ с новым ID; прежний ключ не заменяется до записи нового конверта, поэтому прерванная до записи операция не лишает доступа к старому конверту. При удалении приложения ключ может быть утрачен; на iOS элементы Keychain могут пережить переустановку. Перенос платформенной резервной копии на другое устройство не заменяет JSON-экспорт.

Веб-предпросмотр использует незашифрованное локальное хранилище браузера. Системная блокировка и нативные напоминания в нём недоступны; интерфейс сообщает об этом.

## Проверка

Автотесты ядра хранилища используют реальный AES-GCM Node.js и тестовые адаптеры хранения. Они покрывают миграцию, Unicode, свежий IV, ошибки записи, повреждённый тег, отсутствие ключа и восстановление. Это не тесты системного Keychain/Keystore или биометрии. Их проверка на реальных iOS/Android устройствах обязательна перед выпуском; [текущий отчёт](VERIFICATION.md).

Источники API: [Expo Crypto SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/), [LocalAuthentication SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/local-authentication/), [ScreenCapture SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/screen-capture/). Типы SecureStore сверены с установленной версией SDK 57.
