## Основные выводы и решения

- **A03/A07:** нужны разные виды экспорта — полный восстанавливаемый профиль и выбранная часть данных. CSV частями полезен для операций, но не заменяет резервную копию всей модели. Полный JSON и `.ladbackup` уже существуют; расширяем один механизм.
- **A06:** по уточнению пользователя после импорта/восстановления нужен отдельный экран со сводкой, после экспорта — подтверждение сохранения. Отмена системного меню не считается сохранением; при отсутствии системного подтверждения факт может явно подтвердить пользователь.
- **A26:** выполнен **только анализ замены или добавления данных**. Рекомендованы replace полной копии, восстановление в новый профиль и add CSV-операций. Merge полного JSON не входит в первый этап. Массовое редактирование из первоначального A26 исключено; исходный функциональный пункт не закрывается анализом импорта.
- **A04/A05/A10:** сначала написать и выполнить нужные тесты, затем зафиксировать результаты. Отсутствующие физические устройства или измерения нельзя заменить успешным браузерным прогоном. Отчёт A10 теперь содержит замеры Node, отдельные ограничения и выбранные направления оптимизации; физическая приёмка не закрыта.
- **B03/B06/B07/B09/B10:** это границы действующей модели, а не автоматически доказанные дефекты. В задачах определены изменения и решения, сохраняя допустимые отрицательные остатки, обеспеченность целей и защитные лимиты до проверки альтернатив.
- **A09/B11:** пользователь запросил документы с вариантами/планом. Реализация новых фоновых служб, сервера, платных API и реальных платежей в эти аналитические пункты не включена. Последующее поручение T08 разрешило локальную очередь напоминаний и её интерфейс.

## Как вести статусы

Карточка задачи — источник подробного статуса, таблица выше — краткий индекс. Обновлять их вместе. Словарь:

- `planned` — запланировано; есть зависимости или ещё нужны решения.
- `analyzing` — сейчас выполняется анализ до реализации.
- `ready` — можно начинать описанный этап, это не отметка о готовности функции.
- `in_progress` — выполняется реализация или оформление результата.
- `blocked` — указан конкретный внешний блокер и оставшаяся работа; независимые части продолжаются.
- `done` — выполнены критерии, приложены доказательства и время завершения.
- `deferred` — отложено с записанными причиной и решением пользователя.

У каждой карточки сохранять первоначальное время создания, обновлять время изменения со смещением UTC, вести журнал и метку «Исправлено/Выполнено». Для аналитической задачи `done` означает готовый документ, а не появление описанных функций. Частично выполненная задача не получает `done`; перечислить закрытые подпункты. Число тестов и факт успеха брать из реального последнего протокола. Подробные обязательства закреплены в [AGENTS.md](../../../AGENTS.md).
