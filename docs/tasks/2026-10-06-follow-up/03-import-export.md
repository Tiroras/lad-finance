## Анализ и уточнённый объём

[Полные JSON и .ladbackup](../../../src/features/data-transfer/components/BackupSettings.tsx) уже существуют. Восстановление заменяет текущий профиль после подтверждения, а CSV добавляет выбранные операции с проверкой повторов. [CSV-экспорт](../../../src/features/data-transfer/components/CsvExportSheet.tsx) уже фильтруется по периоду и счёту. Требуется согласованный выбор формата/состава, автоматическое разбиение и понятный результат, а не ещё одна независимая реализация копий.

Пользователь уточнил: **после импорта/восстановления — сводка импортированных данных; после экспорта — подтверждение сохранения файла. A26 означает только анализ замены/добавления, массовое редактирование исключено.** Исходный A26 из реестра не считать исправленным этим анализом.

## Принятые аналитические решения

- Сохранить полный JSON и защищённую копию профиля. Обычный маршрут — подтверждённая замена, альтернативный — восстановление в новый профиль по T02.
- Для A07 реализовать CSV-части на неизменяемом снимке с едиными фильтрами, ID набора и последовательной нумерацией. Предел каждой части — 5000 строк данных и 2 000 000 UTF-8 байт вместе с заголовком. Неделимая слишком большая группа прекращает экспорт с объяснением.
- Разделённая покупка/возврат может дать несколько строк одной операции; их сохранять вместе. В универсальном CSV перевод остаётся одной записью с обеими суммами/валютами. Покупка и возврат могут попасть в разные части; это не обещание безусловного обратного восстановления связей.
- Для A26 рекомендованы replace полной копии и add выбранных CSV-операций. Merge полного/выборочного JSON отложен; конфликты ID, остатков, валют и всех связанных сущностей разобраны в записке. Анализ выполнен, реализация merge не требуется.
- Выборочный JSON и атомарный импорт всех CSV-частей не входят в первый этап. Полный большой архив T02 остаётся однофайловым; CSV сохраняет атомарность отдельного импортируемого файла.
- A06 получает два независимых процесса результата: импорт с подтверждённой записью конкретного снимка и экспорт с явно названным источником подтверждения внешнего сохранения.
- Rescue-экспорт связывается с сохранённой ревизией; неподтверждённый UI не выдаётся за содержимое архива. Повтор передачи сохраняет байты; новая генерация `.ladbackup` получает новый файловый хеш. Сравнение расшифрованного содержимого использует версионированную канонизацию и фиксированный контекст миграции.

## Последовательность

1. Расширить существующий интерфейс выбора: полный профиль — JSON / защищённая копия; выбранные операции — CSV. Показывать фактический состав и ограничения до выгрузки. Выборочный JSON не реализовывать в этом этапе.
2. Добавить экспорт CSV частями с пределами импортёра: не более 5 000 принимаемых строк и 2 МБ на часть, с учётом заголовков, UTF-8 и разделённых покупок. В универсальном CSV обе суммы и валюты перевода находятся в одной записи; не создавать искусственные отдельные движения. Не делить файл по строкам без разбора кавычек и переносов.
3. Реализовать импорт: выбор → проверка → предпросмотр → подтверждение → применение → сохранение → сводка. Счётчики получаются при проверке актуального состояния; повторное подтверждение и смена профиля блокируются до завершения. После ошибки записи показывать неподтверждённую запись и повторять сохранение, а не импорт. Одного `queue.flush()` недостаточно; результат относится к конкретному снимку и профилю.
4. Реализовать экспорт: подготовка → файл готов → передача системе → результат неизвестен → подтверждение пользователем либо проверка выбранного файла. При достоверной отмене — отдельный статус, иначе возврат из share-sheet не означает ни сохранение, ни доказанную отмену. Для CSV-набора подтверждать каждую часть отдельно. «Подготовлено», «подтверждено пользователем» и «файл прочитан/проверен» имеют разные даты и смысл.

## Приёмка и проверки

- A06: тесты успешного импорта, отмены, ошибки записи, повторного открытия результата и смены профиля; нет двойного зачисления. Ошибка/отмена экспорта не даёт ложного подтверждения сохранения.
- A07: 20 000 исходных операций экспортируются принимаемыми частями; части считаются по результирующим строкам/байтам. Проверены многострочные и Unicode-поля, повторы, граничные размеры и одиночная слишком большая запись.
- Полный JSON проходит export → import с сохранением связей. CSV не объявляется без потерь для split/refund/debt. Выборочный JSON не выдаётся за готовую возможность.
- Повтор импорта не создаёт дубликаты согласно выбранному режиму. Полная копия проверяется целиком до замены. CSV сохраняет атомарность в пределах файла; при ошибке следующего уже принятые части остаются, и сводка это показывает. Повтор сохранения после ошибки не применяет пакет заново.
- Аналитический критерий A26 выполнен: записка содержит выбранные replace/add и условия будущего merge. Наличие записки не закрывает реализацию A06/A07.

Проверки: типы, модульные тесты CSV/JSON/действий, связанные Playwright в default с синтетикой, нативное сохранение/отмена файлов на iOS/Android; завершённая сквозная функция проверяется по AGENTS. Обновить DATA_PORTABILITY, CSV_IMPORT и FEATURES_CURRENT.
