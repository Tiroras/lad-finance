## Банковский доступ: установленное и неизвестное

Официальные источники проверены **06.10.2026**. Утверждение «все банковские API платные» неверно: существуют бесплатные предложения. Однако необходимо независимо подтвердить **допуск к личным счетам и истории операций**, цену API и полную стоимость эксплуатации. Бесплатный бизнес-API не решает задачу личного бюджета автоматически.

[Комплекс стандартов ЦБ](https://www.cbr.ru/fintech/api/prikladnye-standarty/) содержит методы согласия и получения информации по счетам физических лиц от 19.12.2025. [Итоги за 2025 год](https://www.cbr.ru/about_br/publ/results_work/2025/razvitie-tekhnologiy-i-podderzhka-innovaciy/), обновлённые 20.03.2026, описывают пилоты и рекомендательное использование стандартов. Это подтверждает развитие обмена, но не выдачу «Ладу» доступа. Исторический отчёт не заменяет проверку действующих условий конкретного подключения.

**Уточнение по Альфе.** В релизе 05.06.2023 указаны `GET /pp/v1/operations`, получение детали операции и заказ выписки. [Документация детали операции](https://developers.alfabank.ru/products/alfa-api/documentation/articles/operations-history/articles/operation-details/v1/operation-details) описывает scope `operations-history`, Authorization Code Flow, сумму, направление и статусы `SUCCESS/HOLD/FAILED`. Следовательно, ограничивать обзор Альфы только бизнес-счетами или только балансом ФЛ нельзя. Но наличие метода не доказывает разрешение выдавать этот scope любому приложению. Общая бесплатность не исключает затрат на РКО, инфраструктуру и специальные условия выбранного сценария.

Предел проверки: страницы Альфы изучены по индексированному тексту официального домена; прямое открытие части страниц возвращало timeout/502. Текущая доступность методов, глубина истории, квоты и допуск конкретного партнёра требуют подтверждения до пилота. Авторизация и запросы к банковским API не выполнялись.

## Архитектура и условия перехода

Файлы, банк и OCR возвращают промежуточные данные; адаптеры размещаются в соответствующих разделах `infrastructure`, интерфейс импорта — в `features/data-transfer`. Проверка формата, валют, повторов и финансовых правил остаётся в чистом `domain`. Принятие пакета проходит через `useFinanceActions → update(current => domainAction(...))`; единый `FinanceState` и существующая очередь сохранений сохраняются. Сеть, OAuth и ключи не попадают в domain или формы. Новые зависимости не оправдывают второе финансовое хранилище.

Начать следует с файлов и проверки восстановления (T02/T03). Далее локальные виджеты, QR/OCR и портфель можно оценивать независимо. Сервер проектируется только после принятия конкретного сценария синхронизации, семьи либо банковского подключения и бюджета. Общие секреты партнёра и TLS-ключи нельзя встраивать в мобильную сборку.

**GO для банковского пилота** означает одновременно:

1. Подтверждены право партнёра работать с ФЛ, согласие/отзыв и нужные scopes **счетов и истории**, а не только идентификации.
2. Известны продуктивная среда, квоты, глубина истории, статусы и модель хранения токенов; определены обязанности сторон.
3. Получены применимые условия цены, РКО и сопровождения; оценка укладывается в установленный пользователем предел.
4. Контрольные проверки охватывают повторы, отмены, возвраты, валюты, разрыв связи и отзыв доступа.

Сейчас **GO для локальных прототипов и дальнейшего проектирования; NO-GO для промышленного банковского подключения**, пока пункты 1–3 не подтверждены. Это ограничение допуска и доказательств, не вывод о непосильной цене. Вопросы подготовлены для будущего согласования; письма банкам не отправлялись.

Отключение интеграции останавливает загрузку/доставку и отзывает полномочия, сохраняя принятые локальные записи. Удаление серверных данных — отдельное действие. Отключение котировок оставляет ручную оценку с датой; удаление виджета не меняет учёт. Уже отправленный платёж при отключении нельзя автоматически считать отменённым.

## Три сценария затрат

| Сценарий                                   | Регулярные расходы                                                                                                                                                                           | Решение                                                                                                            |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **A. Автономный учёт**                     | Банковский API: **0 ₽**; собственный сервер: **0 ₽**, поскольку их нет. Остаются разработка, проверки устройств, публикация и поддержка; лицензии выбранных компонентов оцениваются отдельно | Рекомендуемый старт, без обязательной сервисной подписки                                                           |
| **B. Перенос копий в облако**              | A + тариф выбранного пользователем хранилища/дополнительного объёма; банковский API и сервер «Лада» по-прежнему не нужны                                                                     | Цена не задана без поставщика и объёма. Автоматическая синхронизация и семейный доступ в этот сценарий не включены |
| **C. Промышленное банковское подключение** | A + применимое РКО/партнёрский тариф + инфраструктура + сопровождение интеграции; отдельно расходы на полноценную синхронизацию, если она выбрана                                            | Расчёт до GO, запуск после допуска. Бесплатный API уменьшает одну статью, не обнуляет весь сценарий                |

Формула C: **Cₘ = F + N × pₙ + Q × pᵩ + S + D + M**, где F — фиксированные услуги/РКО, N и Q — число оплачиваемых подключений и запросов, pₙ и pᵩ — их единичные цены, S — сервер/БД/хранилище/трафик, D — доставка/наблюдение, M — сопровождение. Неиспользуемые либо включённые статьи исключаются. Для платежей отдельно добавляется подтверждённая комиссия; разово учитываются интеграция, договорная и защитная проработка.

Для оценки задаются число пользователей/счетов, запросов в сутки, глубина истории, объём копий и месячный предел. Неизвестные цены остаются неизвестными. Рекомендация сейчас: **A → при необходимости B; C — однобанковский пилот после допуска**, без обязательства реализовать все восемь направлений одновременно.
