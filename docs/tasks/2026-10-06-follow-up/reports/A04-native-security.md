Первый вход target завершил все четыре шага настройки с нулевыми остатками. Последующие шаги используют фактическое точное имя, профиль не удалялся и не пересоздавался.

Read-only разбор имени подтвердил: поле до ввода было пустым, в `commands.json` один `inputText`, а `device-logcat` содержит 21 character code точного `A04-20261015-Transfer`, код `65` (A) один раз. ## Предел подтверждения

A04 остаётся открытым: не выполнены физические Android/iOS, межплатформенный перенос, потеря отдельного локального ключа, проверка краткой вспышки/позднего успешного callback и перечисленные в матрице случаи. Успешный перенос между двумя независимыми Android-установками и полное равенство финансовых данных зафиксированы отдельно. Добавлен воспроизводимый протокол с явными ручными шагами и строгой проверкой неизменности через повторный экспорт/канонический хеш. Проверки физического системного предпросмотра, сильной биометрии, жизненного цикла Keychain/Keystore и отсутствия вспышки данных не подменяются Node-моками или одним снимком дерева доступности.

Перед работой сверены точные версии [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/), [LocalAuthentication](https://docs.expo.dev/versions/v57.0.0/sdk/local-authentication/) и [ScreenCapture](https://docs.expo.dev/versions/v57.0.0/sdk/screen-capture/). На iOS текущий код использует защиту предпросмотра переключателя приложений; запрет обычных снимков там не заявляется. Android использует защиту снимков через Expo ScreenCapture.
