# Отчёты выполнения

Создано: 2026-10-06T15:19:53+04:00. Здесь будут фактические результаты выполнения [задач](../README.md). Сейчас новых прогонов A04/A05/A10 нет; этот файл задаёт состав отчёта, а не сообщает об успешных проверках.

Для каждого отчёта указывать:

1. ID задачи и замечаний, время начала/окончания с UTC-смещением, SHA и незакоммиченные изменения, важные для результата.
2. Режим default / Demo / Fresh, устройство/ОС/тип сборки, синтетический набор данных, размеры и начальные условия. Fresh допустим только в предусмотренной изолированной среде.
3. Команду или воспроизводимые шаги, ожидаемый результат, фактический результат, passed / failed / not-run и ссылку на обезличенные артефакты.
4. Для замеров — единицы, число повторов, прогрев, исходные наблюдения, распределение и контроль финансового результата. Не переносить время Node или эмулятора на физический телефон.
5. Вывод, предел подтверждения, варианты решения с основанием, выбранное действие и связанные следующие задачи.

Планируемые документы T01:

- `A04-native-security.md` — матрица системной защиты и восстановления отдельно для iOS/Android.
- `A05-save-interruption.md` — сбои записи и остановка процесса до/после подтверждения сохранения.
- `A10-performance.md` — измерения больших данных и возможные решения по результатам.

Не создавать заглушку с «тест пройден». Если часть проверки недоступна, фиксировать конкретную причину и оставшуюся работу. Сырые логи и снимки с тестовыми данными хранить по правилам проекта в `test-results/`; переносить в документацию только нужные обезличенные сведения. Исторические протоколы остаются в [VERIFICATION.md](../../../VERIFICATION.md).
