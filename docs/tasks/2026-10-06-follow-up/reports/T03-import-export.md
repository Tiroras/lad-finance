## Реализация и границы

[CSV writer](../../../../src/domain/csvExport.ts) разделяет операции на группы строк, затем на файлы до **5000 логических строк данных / 2 000 000 UTF-8 байт**, включая BOM, заголовок и CRLF. Группа одной разделённой покупки или одного возврата неделима; слишком большая группа отклоняет весь набор. Универсальный перевод остаётся одной строкой с обеими суммами/валютами. Число файлов определяется фактическими строками и байтами. CSV по-прежнему не является полным переносом связей split/refund/debt.

Подготовленный набор фиксирует профиль, дату, фильтры, снимок, имена и байты. Повтор передачи использует тот же файл; новые условия требуют новой подготовки. Для каждой части независимы подготовка, неизвестный результат передачи, ручное подтверждение и проверка точного файла чтением. Отметки последнего набора хранятся отдельно для профиля, без строк CSV; после закрытия окна для новой передачи нужны новые байты. Полная JSON/парольная копия также сохраняет подготовленные байты в открытом окне для точного повтора без нового шифрования. Возврат из share/download не считается доказательством внешнего сохранения.

[Контроллер результата](../../../../src/state/finance/importController.ts) сохраняет намерение и конкретный снимок в памяти текущего запуска. CSV применяется один раз к актуальному состоянию; после ошибки записи повтор проверяет/сохраняет тот же снимок с теми же ID. Точный readback подтверждает запись, несовпадение не маскируется одним `flush()`. До разрешения неподтверждённого результата блокируются изменения учёта и смена профиля. Отдельно подтверждённое открытие снимка устройства читает его и меняет только память; при неудачном чтении текущая память сохраняется.

JSON-замена, CSV и восстановление в новый профиль открывают сводку состава и остатков. Неизвестный прежний состав явно обозначен, остатки относятся к моменту импорта. Результаты доступны через **Профиль → Данные и копии → Результаты импорта** до перезапуска, без хранения финансовой сводки в служебных метаданных. Новому профилю добавляется результат уже проверенной записи, без второго сохранения. Для восстановления повреждённого хранилища неподтверждённый результат доступен на экране загрузки; память не объявляется заменённой до подтверждения записи.

Выборочный JSON, merge полных копий, массовое редактирование и общая атомарная транзакция всех CSV-файлов не реализуются. Каждый импортируемый CSV-файл атомарен отдельно; ошибка следующего не отменяет предыдущие. [Пользовательские маршруты](../../../DATA_PORTABILITY.md), [CSV и повтор сохранения](../../../CSV_IMPORT.md#результат-импорта-и-повтор-сохранения).

## Найденные ошибки и исправления

Независимое ревью выявило **P2**: при восстановлении профиля B из открытого профиля A повтор после отказа подготовительного сохранения A мог подтвердить уже совпадающий B и потерять неподтверждённую память A. Исправление требует завершить подготовку восстановления перед точным подтверждением B. Добавлены два случая: такой retry и отдельный readonly escape, который не должен сам сохранять A. Оба вошли в финальные **17/17** controller cases в Chromium.

Первый полный браузерный прогон выявил отдельную **ошибку продукта**: соседние `BackupVerification` и `BackupPicker` использовали одинаковый `key={profile}`. После появления условных блоков React мог дублировать элементы проверки копии и нарушать повтор ввода пароля; в одном failure было десять кнопок проверки. У компонентов заданы разные ключи `verification-…` и `restore-…`. Первый Demo-прогон остановлен после двух B10-отказов: **16 passed / 2 failed / 1 interrupted / 141 did not run**. Лог `e2e-full.log` и `full-first-demo-results/` сохранены. Целевой повтор B10/export после исправления: **6 passed / 1 failed**. Оставшийся отказ — старый точный селектор сообщения проверки без добавленной даты; receipt уже подтвердил чтение файла. Селектор уточнён, проверки receipt сохранены. Во втором полном прогоне все четыре B10-сценария прошли; отдельная регрессия этого прогона описана далее. Это продуктовая регрессия, в отличие от ошибок сценариев ниже.

Следующий полный Demo-прогон завершился **159 passed / 1 failed**, 5,2 мин (`e2e-full-final.log`, `full-second-demo-results/`); personal/Fresh не запускались. Это ещё одна **регрессия продукта**: обычное восстановление неактивного повреждённого профиля B автоматически открывало его вместо сохранения здорового активного A. Ожидание прежнего контракта сохранено: подтверждённое восстановление B не должно менять активный профиль/предпочтение; явное действие чтения снимка устройства остаётся отдельным переходом. Исправлены контроллер и provider: обычное восстановление B сохраняет активный A и его предпочтение; `appliedRevision` для B, не установленного в память, остаётся `null`. Отдельное явно подтверждённое открытие B из снимка устройства сохраняет прежний смысл. Новый controller case и существующий UI-сценарий прошли: целевой повтор **4/4**, 9,2 с (`browser-inactive-profile-fix.log`), включая три набора с **34** случаями; TypeScript прошёл (`typecheck-inactive-fix.log`). Последующий третий полный прогон `e2e-full-third.log` прошёл во всех трёх режимах, включая этот сценарий в Demo и default.

Первые неуспехи UI сохранены в логах и не объявлены дефектами продукта:

- `browser-import-first.log`: 3 passed / 7 failed. JSON fixture не установился из-за неопределённого порядка двух init scripts; часть CSV-сценариев нажимала перекрытый backdrop «Закрыть окно» вместо кнопки окна, другие требовали уточнения селекторов.
- `browser-round2.log`: 10 passed / 3 failed. После объединения init scripts JSON fixture устанавливался, но browser bundle не был явно привязан к `globalThis` для последующего `page.evaluate`. Финансовые assertions этих трёх тестов не выполнялись.
- `browser-backup-round3.log`: сервер не стартовал из-за рабочего каталога временного конфига; ни один тест не запускался.
- `browser-backup-round3b.log`: все три JSON-сценария дошли до подтверждённой сводки, но общий селектор суммы находил ещё и скрытый главный экран. Селекторы ограничены диалогом без ослабления финансовых ожиданий; round4 **3/3 passed**.

Начальные логи, trace и снимки сохранены; успешные повторы не заменяют историю неуспехов. Обновление старых UI-проверок учитывает новое открытие подтверждённого результата и новую нумерацию CSV-файлов.
