Режим данных — default: `demo:false`, синтетическое имя, фиксированные seed/дата, без Fresh. Harness работает с памятью и отдельным `test-results/t01-a10`; личные профили и хранилище приложения не открывает.

Для повторной серии 15.10.2026 запуск A04-эмулятора, полные npm-тесты и сборки отложены до окончания замеров. Обычная нагрузка рабочего стола, температура и частота CPU не контролировались. Эта серия не смешивается с историческими наблюдениями 06.10.2026: тогда Android-эмулятор продолжал работать, а предварительная серия от 17:39:33 была прервана SIGINT из-за параллельной сборки и сохранена как `t01-a10-pilot`.

Каждая основная операция имеет 3 прогрева. История/поиск, прогноз и модель vault — 30 измеренных повторов, p95 nearest-rank (29-е из 30); JSON/CSV/AES/парольный файл/KDF — 10 повторов, только медиана/максимум. GC запускается перед каждым повтором вне измеренного интервала; проверки результата выполняются после таймера. Это контролируемый baseline, а не естественное распределение пауз сборщика мусора в приложении. Серии последовательны, без смешивания размеров. Сырые наблюдения сохраняются после каждого повтора.

Холодный Node-процесс запускается 10 раз для каждого размера без прогрева. Отдельно записаны wall time запуска Node + загрузчика tsx + импортов + чтения/валидации и таймер самого чтения/валидации. Это не время появления защищённого интерфейса приложения. Дочерний процесс проверяет число операций; полное равенство JSON и финансовые инварианты проверяет основной harness.

## Данные и точность

Генератор [fixtures.ts](../../../../tests/performance/fixtures.ts) использует seed `20261006`, дату расчёта `2026-10-06`, исторические даты операций `2025-10-07…2026-10-05` и собственные стабильные ID. Наборы имеют ровно 1 000 / 5 000 / 20 000 операций и проходят настоящие `checkedBackupContent` и `decodeBackup`. Для каждого размера сохранён JSON и manifest с числом сущностей, UTF-8 байтами, длиной UTF-16, SHA-256 и контрольными суммами.

Каждый набор содержит 5 счетов, RUB/USD/JPY/KWD с 2/2/0/3 знаками, 8 категорий, 1 цель, 1 долг, 40 регулярных платежей и 20 планов дохода. Графики day/week/month/year имеют интервалы 1–3, даты конца месяца, пропуски и историю суммы; прогноз включает просрочки. На каждые 10 операций: split-покупка, её частичный возврат, обычный доход, обмен RUB→USD с двумя суммами, расход JPY, доход KWD, получение/погашение основной суммы долга, обычный RUB-расход и расход USD. У каждого возврата есть существующая покупка, долг не становится отрицательным, цель обеспечена накоплениями.

[oracle.ts](../../../../tests/performance/oracle.ts) не вычисляет ожидаемые суммы через функции приложения: используется алгебра десяти операций и отдельный календарь на UTC-календарных компонентах. Проверяются точные целые остатки каждого счёта в его минимальных единицах, доход/расход без переводов и основной суммы долга, распределение split/refund по категориям, остаток долга, поиск, начальный/конечный прогноз и все 90 дневных остатков. Календарный oracle не импортирует `forecast`, `scheduleDates`, `shiftDate` для вычисления ожидаемых дат; `forecast` вызывается только как проверяемый код.

CSV дополнительно проверяется по всем четырём валютам, знакам и обеим сторонам каждого перевода. Для такой проверки экспорт разбит на полные блоки по 1 000 операций, чтобы части покупок и возвраты оставались связаны, а каждый CSV проходил настоящий парсер. CSV остаётся плоским экспортом, не резервной копией связанной модели.

Отдельные граничные проверки:

| Сценарий                                                           | Результат и смысл                                                                                                                           |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Валидный JSON ровно 5 000 000 UTF-8 байт с кириллицей              | `passed`: новое сохранение допускается                                                                                                      |
| Тот же JSON + 1 ASCII-байт                                         | `passed` как негативный тест: сохранение отклонено до записи                                                                                |
| Валидный старый JSON >5 МБ UTF-8, но <5 млн UTF-16 символов        | `passed`: читается; уменьшение разрешено с прежним размером; новый обычный экспорт отклоняется                                              |

Генератор не зависит от текущего дня. Сам штатный `decodeBackup` использует локальный день для запрета будущих операций; прогон предназначен для даты не раньше 2026-10-06. Это ограничение валидатора зафиксировано, часы процесса не подменялись.

## Что именно измеряет сохранение и криптография

`vault_save_memory_adapter` вызывает настоящий `createVault().save()` с валидацией, сериализацией, шифрованием, проверкой расшифрования и прочитанной записи. Storage и key service заменены Map, AES предоставлен Node WebCrypto. Сохраняется тот же валидный снимок. Это стоимость алгоритма vault; здесь нет SecureStore/AsyncStorage, новой ревизии, провайдера и подтверждения сохранения ревизии. Контракт подтверждения отдельно проверяется в [A05](A05-save-interruption.md).

`node_file_write_fsync_read` записывает plaintext только в отдельный синтетический временный файл, вызывает `fsync`, читает и сравнивает байты, затем файл удаляется. Это справочное измерение файловой системы Mac, не адаптер мобильного приложения и не гарантия переживания сбоя питания.

Полная `.ladbackup` использует настоящий `encryptBackup`/`decryptBackup`, фиксированные 600 000 PBKDF2-SHA256 итераций и AES-256-GCM, с браузерным адаптером на Node WebCrypto. При каждом расшифровании сравнивается весь `FinanceState`. Отдельно замерен используемый нативным адаптером JS KDF `derivePasswordKey` на Node и проверено равенство ключа WebCrypto. Нативный Expo AES и скорость Hermes здесь не измерены; параметры защиты не снижались. Время системного файлового меню отсутствует.

## Решение по измеренным ограничениям

1. **Приоритет — повторные обходы связанных возвратов.** При росте 5k → 20k (в 4 раза) медиана всей истории выросла с 46,91 до 752,65 мс, CSV — со 125,39 до 1 784,64 мс, валидации JSON — с 57,96 до 689,41 мс. В [transactionAmounts.ts](../../../../src/domain/transactionAmounts.ts) поиск исходной покупки и связанных возвратов повторяется по всему массиву; [csvExport.ts](../../../../src/domain/csvExport.ts) дополнительно вычисляет распределение возврата дважды. Из кода и характера роста следует кандидат на исправление: индекс операций по ID и возвратов по покупке, общий для одного расчёта, плюс однократное вычисление распределения. Это обоснованная гипотеза, а не CPU-профиль отдельных функций. Перед внедрением сохранять хронологию частичных возвратов и точное распределение копеек, после — повторить этот же oracle и серию. В T01 финансовый код не менялся.
2. **Криптография требует отдельной нативной проверки ожидания.** JS PBKDF2 дал медиану 10,21 с против 73,72 мс Node WebCrypto. Это разные реализации на одном Node-стенде, не сравнение Android и Web. У JS KDF уже есть `asyncTick: 8`, у формы — состояние «Защищаем копию…»; длительность целиком не означает непрерывную блокировку. Отдельные наблюдения выше подтвердили длительное ожидание отказа неверного пароля и успешного создания копии на перегруженном эмуляторе. Выбран следующий шаг: повторить эти пути на ненагруженном release/Hermes, измерить отзывчивость формы и проверить доступный безопасный платформенный KDF, если задержка подтвердится. 600 000 итераций, формат и требования к паролю не менять.
3. **Замена хранилища и оптимизация прогноза пока не обоснованы этим стендом.** Для stress 20k чистый прогноз имеет p95 4,94 мс, запись/синхронизация/чтение файла Mac — медиану 13,15 мс, модель vault — 743,34 мс. Последняя включает дорогую валидацию; это не основание приписывать задержку SecureStore или выбирать SQLite. Сначала разделить фактический нативный путь до ACK ревизии и отрисовку. Цели физических устройств по этим числам не закрываются.
4. **Лимиты не повышать.** 20k имеет валидный JSON 3 281 004 байта, но полный CSV разворачивается в 24k строк и штатно не импортируется целиком. Legacy 5 742 645 байт читается прежним форматом и не проходит обычный экспорт. T02/A03 должен дать отдельный ограниченный перенос; пик памяти всего Node-harness не подтверждает пригодность такого архива на телефоне.

Разделение результата по средам:

| Среда                                        | Результат A10                       | Граница доказательства                                                                                                          |
| -------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Node v22.21.1 / V8, macOS, default synthetic | `passed`                            | Валидность, точные суммы и описанные времена алгоритмов; 700 наблюдений и 30 холодных процессов                                 |
