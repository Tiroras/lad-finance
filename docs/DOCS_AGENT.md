# Агент документации

`docs_agent` создаёт и обновляет русскую документацию «Лада» по порученной задаче. Определение находится в [docs_agent.toml](../.codex/agents/docs_agent.toml). Агент сверяет описание с кодом, требованиями и протоколами проверок; при запросе на обновление вносит правки, при запросе только на анализ возвращает замечания.

Модель, разрешения и MCP наследуются от родительского сеанса; отдельные глобальные настройки не нужны. Формат роли описан в [официальной документации OpenAI](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Область ответственности

| Документ                                                             | Что поддерживает агент                                                                        |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| [README.md](../README.md)                                            | Команды, предусловия запуска, режимы, навигацию по возможностям проекта                       |
| [AGENTS.md](../AGENTS.md)                                            | Краткие обязательные правила, ссылки на подробные инструкции и условия их чтения              |
| [ARCHITECTURE.md](ARCHITECTURE.md)                                   | Размещение файлов, зависимости, публичные интерфейсы, поток состояния и композицию приложения |
| [DEVELOPMENT.md](DEVELOPMENT.md)                                     | Режимы и условия проверок, CI, ведение документации, задач, отчётов и артефактов              |
| [FEATURES_CURRENT.md](FEATURES_CURRENT.md)                           | Реализованные функции, ограничения и матрицу подтверждений                                    |
| Тематические документы в `docs/`                                     | Финансовые правила, импорт/экспорт, защиту, обучение и другие затронутые области              |
| [VERIFICATION.md](VERIFICATION.md) и связанные отчёты                | Фактические результаты с датой, платформой, режимом, сборкой и ограничениями                  |
| [Очередь follow-up](tasks/2026-10-06-follow-up/README.md) и карточки | Согласованные статусы и журнал при подтверждённом изменении состояния задачи                  |

Агент расширяет существующие документы, сохраняет полезные ссылки, терминологию и чужие правки. Новая инструкция создаётся, когда у неё есть отдельная ответственность; переписывание всего раздела ради оформления не требуется. `AGENTS.md` остаётся краткой корневой инструкцией, а подробные правила поддерживаются в профильных документах.

## Согласованность инструкций

Перед работой агент читает [правила актуализации документации](DEVELOPMENT.md#актуализация-документации). В каждой порученной задаче он оценивает влияние изменений на инструкции и обновляет затронутые разделы:

- При изменении структуры файлов, зависимостей, публичных интерфейсов, потока финансового состояния, провайдеров или навигации сверяет `ARCHITECTURE.md` с кодом и `tests/architecture.test.ts`.
- При изменении npm-команд, режимов, условий тестирования, CI, порядка ведения задач, отчётов или артефактов сверяет `DEVELOPMENT.md` с `package.json`, скриптами, конфигурациями и требованиями задачи. Описания запуска согласует с README, обязательных проверок — с `AGENTS.md`.
- При переносе или переименовании инструкции обновляет затронутые ссылки, якоря и указания, когда её читать. Подробности сохраняет в профильном документе; в `AGENTS.md` оставляет обязательные правила и ссылки, не возвращая удалённые дубли.

Нарушение архитектуры или пропуск обязательной проверки не становится основанием ослабить инструкции: агент сообщает о расхождении. Если документы уже согласованы, он не меняет их ради формального обновления.

## Основания для изменений

Передайте агенту задачу, файлы, коммит или диапазон изменений и доступные результаты проверок. Для текущей незакоммиченной работы учитываются staged, unstaged и относящиеся к задаче untracked-файлы. Если параллельно меняется код, согласуйте состояние, по которому обновляется описание, и перепроверьте затронутые выводы после новых правок.

Реализация функции и её проверка описываются отдельно. Чтение кода подтверждает наличие реализации; существование теста не подтверждает успешный запуск. Исторический браузерный прогон не становится проверкой текущей нативной сборки. Неизвестные сведения отмечаются явно, а результаты переносятся только из реальных протоколов по [правилам отчётов](tasks/2026-10-06-follow-up/reports/README.md).

При изменении функции агент согласует тематическое описание и обзор возможностей по правилам проекта. Дату сверки и базовый коммит указывает по фактическому состоянию; без смыслового изменения дату не обновляет. Историю сохраняет, новые проверки добавляет отдельно. Статусы карточки и индекса меняет вместе в рамках порученной задачи; завершённый анализ не обозначает готовую реализацию.

Если код расходится с требованиями, агент сообщает о расхождении основному исполнителю. Изменение приложения, тестов или финансовых правил требует соответствующего объёма поручения. В документации можно честно описать наблюдаемое ограничение; подтверждённый дефект нельзя молча превратить в ожидаемое поведение.

## Результат и проверка

Результат — обновлённые документы либо запрошенный отчёт. Агент проверяет пути, ссылки и якоря, сверяет команды с конфигурацией и их предусловиями, форматирует изменённые Markdown-файлы через Prettier и выполняет `git diff --check`. Полный прогон приложения для документальной правки не требуется. Примеры содержат только синтетические данные.

В ответе перечисляются изменённые документы, основания для правок, выполненные проверки и оставшиеся неизвестные сведения или расхождения. Если документы уже соответствуют задаче, агент сообщает об этом без искусственных правок.

## Примеры поручений

> Используй docs_agent: обнови документацию по текущим изменениям импорта CSV. Сверь код и тесты, согласуй инструкцию импорта и обзор функций. Результаты проверок бери только из существующих протоколов.

> Используй docs_agent: после переноса модулей и изменения команд проверок актуализируй ARCHITECTURE.md и DEVELOPMENT.md. Согласуй ссылки и краткие правила в AGENTS.md и README, сохрани границы архитектуры и требования проверок.

> Используй docs_agent: перенеси подтверждённые результаты приложенного нативного протокола в документацию. Сохрани дату, устройство, режим, сборку и ограничения; не закрывай задачу, если часть критериев не выполнена.

> Используй docs_agent: только проверь соответствие README и тематической документации текущему коду. Верни список расхождений, файлы не меняй.

После добавления определения откройте новый сеанс Codex в репозитории. Если роль недоступна, основной агент может прочитать её TOML и выполнить процедуру сам, явно указав такой способ работы. Название `docs_agent` используется обычным текстом, без `$`; это не команда npm.
