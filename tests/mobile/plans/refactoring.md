## MREF-01 — сумма, ввод даты и валидация

**Режим:** demo. **Исходный профиль:** Демо после общей подготовки, тестовых
записей нет. **Дата устройства:** `2026-10-04`.

1. Открыть новую операцию, выбрать «Доход». Ввести сумму последовательно
   `1250.50` и имя `MaestroRefactor-20261004-Income`.
2. Проверить видимое форматирование суммы `1 250.50`: поле сохраняет введённый
   десятичный разделитель. Перевести фокус на
   название и обратно: цифры и десятичная часть сохраняются.
3. Очистить «Дата операции», ввести `29022025`. Поле показывает
   `29.02.2025`; касание самого поля не открывает календарь.
4. Убрать клавиатуру, нажать «Добавить операцию». Форма остаётся открытой;
   виден текст «Введите существующую дату в формате ДД.ММ.ГГГГ.».
   Операция не добавлена. Проверку отсутствия записи выполнить после
   закрытия формы и поиска по точному имени, затем начать заново с теми же
   суммой и именем, чтобы не судить о сохранении только по наличию ошибки.
5. Во второй форме ввести корректную дату цифрами `03102026`: результат
   `03.10.2026`. Ввести заметку `Mask-Note-20261004`, сохранить.
6. Найти запись на вкладке операций по полному имени. Результат ровно один,
   группа «Вчера», строка суммы `+1 250,50 ₽`.
7. Открыть запись: сумма `1 250,5` (повторное открытие использует локальный
   разделитель и убирает завершающий ноль), дата `03.10.2026`, заметка сохранена.

**Повтор:** после общей адресной очистки тестовых записей. Неверная дата
сама по себе не должна создавать запись или менять остатки.

## MREF-02 — редактирование, календарь и перезапуск

**Режим:** demo. **Исходные данные:** единственная запись дохода после
MREF-01. **Дата устройства:** `2026-10-04`.

1. В открытой форме дохода изменить последние две цифры суммы с `50` на
   `75` с удалением и последующим вводом. Перед вводом подтвердить положение
   курсора в конце; если Maestro не позволяет доказать положение курсора,
   отдельно выполнить полную замену поля и не заявлять проверку редактирования
   в середине строки. После ввода `1250.75` поле показывает `1 250.75`;
   после сохранения и повторного открытия — `1 250,75`.
2. Открыть «Открыть календарь: Дата операции». Осмотреть выбранное
   `3 октября 2026 г.`. Нажать «Отмена»: значение остаётся `03.10.2026`.
3. Открыть календарь повторно, выбрать `4 октября 2026 г.`. Календарь
   закрывается, дата показывает `04.10.2026`, сумма остаётся `1 250,75`.
4. Сохранить изменения. Поиск по полному имени показывает одну запись,
   `+1 250,75 ₽`, группа «Сегодня». Повторно открыть форму и проверить
   `1 250,75` / `04.10.2026`, затем закрыть.
5. Остановить и снова запустить приложение без `clearState`. Подтвердить
   текущий профиль Демо. Открыть операции, найти запись, открыть форму:
   сумма, дата и заметка остались прежними; копия операции не появилась.

**Повтор:** вместе с MREF-01 после общей очистки. Fresh здесь запрещён,
поскольку проверяется сохранение между запусками.

## Границы доказательств

- На этапе первоначального планирования MREF-01, MREF-02 и MREF-03 ещё
  не выполнялись. Фактический результат новой сборки записан ниже.
- Сценарии проверяют новую сборку на Android. iOS не осмотрен.
- Нативное редактирование в середине строки, выделение диапазона и точная
  позиция каретки требуют отдельного наблюдения, если не подтверждены
  реальными действиями; браузерные тесты не доказывают эти свойства Android.
- Пагинация свыше 60 записей, возвраты, части покупки и движения основной
  суммы долга требуют модульных и браузерных проверок рефакторинга. Три
  тестовые операции не подтверждают эти случаи на устройстве.
- Сценарии не проверяют Fresh и не меняют защиту, хранилище, импорт/экспорт,
  валютные курсы или реальные профили. Проверки остальных режимов отдельно
  выполняются основным агентом по проектному набору тестов.

## Реализованный сценарий и подготовленная сборка

`tests/mobile/demo/refactoring.yaml` ограничен одной собственной записью
`MaestroRefactor-20261004-Income`. MREF-01 и MREF-02 реализованы с полной
заменой суммы. Из MREF-03 реализованы поиск по имени и заметке с другим

«Все счета», точные суммы строки и округлённые итоги, адресное удаление и
восстановление исходного состояния. Матрица трёх записей выше остаётся
планом расширенной проверки, её нельзя считать выполненной этим YAML.

Предусловия сохранённого YAML: локальная дата `2026-10-04`, завершённое
приветствие, Demo с шестью исходными примерами, доходами `120 000 ₽` и
расходами `34 605 ₽`, отсутствие тестового префикса. Начальные и конечные
итоги проверяются явно. После прерванного запуска удаляется только точно
известная тестовая запись через «Удалить операцию» → «Да, удалить».

Актуальная release-сборка Demo собрана из изменённых исходников командой:

```sh
docker compose run --rm android test --mode demo --device emulator-5554 tests/mobile/smoke.yaml
```

Исторический smoke прошёл до согласованного пользователем удаления
`tests/mobile/smoke.yaml`; для дальнейших повторов используется YAML выше.
APK — `test-results/mobile/docker/app-demo.apk`, SHA-256:
`6059122881b43f589d795baa020670d24112ec3562bff015d1fbaedf816569d2`.
Перед финальной проверкой хеши изменённых участков сверены с
`test-results/mobile/refactoring-exploration/source-identity.json`;
после сборки код продукта не менялся. Режим Demo подтверждён доступным
профилем. `--no-build` ниже повторно проверяет именно эту сборку.

При интерактивном исследовании обнаружена ошибка сценария: нажатие в центр
длинного заполненного поиска ставит каретку внутри текста, поэтому
`eraseText` оставлял хвост `004-`. Иерархия сохранена в
`test-results/mobile/refactoring-exploration/filtered.json`.
Исправленная последовательность проверяет поиск по заметке после
перезапуска и вводит новый запрос в пустое поле; суммы и условия поиска
сохранены. Это одновременно проверяет сохранение записи между запусками.

Первый CLI-запуск остановился до UI из-за кодировки русского `name`
в пути отчёта Maestro. Имя YAML заменено на `refactoring`, для контейнера
явно задана UTF-8 locale. Следующий запуск выявил, что нажатие на уже
выбранный Demo оставляет окно профилей открытым: теперь переключение
выполняется только при другом текущем профиле, а проверка Demo обязательна
в обоих случаях. Артефакты этого сбоя:
`test-results/mobile/docker/2026-10-04_013708/refactoring/`.
