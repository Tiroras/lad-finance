# Проверка улучшений бюджетов и формы операции

Основание: [исследование бюджетов](ux-budget-discovery.md), сценарии MUBD-02,
MUBD-03, MUBD-04 и проект MUBD-07. Роль исполнения: `maestro_generator`.
Файл фиксирует только проверяемый объём текущего изменения, без повторения
полной экскурсии и без исследования с участниками.

  Устройство подтверждено через `list_devices`; все действия выполняет
  один агент последовательно. После восстановления соединения временный
  локальный MCP использовал Viewer <http://127.0.0.1:10010/>.

  обновляет основной агент полным build и `adb install -r`, сохраняя данные.
  Проверка новой функциональности начата после его READY и полной сборки.
  APK: `test-results/mobile/docker/app-demo.apk`; SHA-256 установленной и

  Хеш установленной APK повторно сверен после восстановления эмулятора.

## MUX-01 — расшифровка месячного бюджета

1. Подтвердить исходные данные; «План» → «Бюджеты».
2. Раскрыть «Расходы за период: Продукты».
3. Сверить период 1–31 октября, общую сумму 3 825 RUB и две операции
   с датами и точными суммами 1 485 и 2 340 RUB.
4. Открыть «ВкусВилл», проверить компактный выбор категории и сохранение
   перед дополнительными деталями. Закрыть неизменённую форму.
5. Убедиться, что подтверждение отмены не появилось, раскрытие сохранилось.
   Открыть прежнее «Изменить бюджет: Продукты» и закрыть без сохранения.

Ожидается: просмотра достаточно для объяснения суммы. Просмотр, открытие
формы и её отмена не создают и не изменяют финансовых записей.

## MUX-02 — новый черновик и способы закрытия

1. «Обзор» → «Расход»; закрыть нетронутую форму без диалога.
2. Повторно открыть расход, заполнить 320 RUB и `UX-Improve-Expense`.
   Осмотреть поле суммы с цифровой клавиатурой, затем скрыть клавиатуру.
3. Крестик «Закрыть» вызывает подтверждение потери данных.
   «Продолжить ввод» возвращает сумму и название без изменений.
4. Android Back вызывает то же подтверждение. Повторный Android Back
   отменяет только подтверждение, возвращая тот же черновик. Жест вниз за
   верхнюю область окна также вызывает подтверждение.
5. «Сбросить и закрыть» закрывает черновик. Новая форма пуста;
   сохранённых операций по имени теста нет.

Ожидается: обычная отмена без изменений остаётся быстрой, изменённый
черновик защищён. Жест выполняется в области заголовка, подтверждённой
снимком и иерархией. Координаты не используются вместо селекторов кнопок.
Закрытие по фону проверяется только при доступном элементном селекторе;
невозможность проверить отмечается отдельно, без фиктивного результата.

## MUX-03 — создать, исправить, удалить собственную запись

1. Создать `UX-Improve-Expense`, 320 RUB, «Продукты», «Основная карта»,
   04.10.2026. «Добавить операцию» завершает запись без диалога отмены.
2. Раскрыть бюджет: расход 4 145 RUB, в составе есть собственные 320 RUB.
3. Открыть свою запись, изменить сумму на 321 RUB; закрыть и выбрать
   «Продолжить ввод». Данные черновика сохранены.
4. «Сохранить изменения» находится до дополнительных деталей и закрывает
   окно без подтверждения потери данных. Бюджет остаётся раскрыт,
   расход становится 4 146 RUB, вклад записи — 321 RUB.
5. Открыть свою запись, изменить сумму без сохранения и подтвердить сброс.
   Сохранённая сумма остаётся 321 RUB.
6. Удалить только `UX-Improve-Expense` через «Удалить операцию» →
   прокрутка к «Да, удалить» → подтверждение. Диалог отмены изменений
   не появляется.
7. Проверить бюджет 3 825 RUB, отсутствие тестовой записи, 6 операций,
   доходы 120 000 RUB, расходы 34 605 RUB и «Можно потратить» 54 012 RUB.

Ожидается: выбор и изменение операции из расшифровки возвращают к тому же
контексту бюджета, финансовые итоги пересчитываются. Удаление собственной
записи восстанавливает исходные данные и допускает повторный запуск.

## Фактический интерактивный результат

MUX-01, MUX-02 и MUX-03 пройдены последовательно через Maestro MCP на
новой Demo-сборке. Новые подписи подтверждены иерархией устройства перед
включением в YAML. Для жеста использован `swipe.from.id: sheet-drag-area`,
без координат. Сохранение и удаление завершились без диалога отмены.
Android Back на самом подтверждении вернул прежний черновик; сумма и
название остались введёнными. После удаления записи восстановлены бюджет
3 825 RUB, 6 операций, доходы 120 000 RUB, расходы 34 605 RUB и доступная
сумма 54 012 RUB. Приложение оставлено на «Обзоре» в Демо.

Снимки (осмотрены визуально): `08-budget-evidence.png`,
`10-edit-compact.png`, `14-keyboard.png`, `16-dirty-confirm.png`,
`26-budget-edited.png`, `33-restored-history.png`, `35-restored-home.png`.
Все находятся в `test-results/mobile/ux-improvements/`. Сохранение в форме
исправления целиком видно на первом экране без клавиатуры; цифровая
клавиатура оставляет видимыми сумму и название. Длинная подпись раскрытия
дополнительных полей не перекрывает кнопку сохранения.

## Окружение и повторный запуск

Первый inline-запуск не дошёл до новых функций: эмулятор завершился,
Maestro вернул `Device server died ... UNAVAILABLE`, ADB не видел устройств.
Повторный запуск Pixel_8 остановился на системном crash-report dialog.
Выполнен cold boot с `-no-snapshot-load -crash-report-mode never`; данные
приложения не очищались. Подключённый MCP держал старое соединение, поэтому
использован временный отдельный локальный `maestro mcp`. Новый сеанс
подтвердил исходные суммы и актуальный APK. Одна исследовательская команда
без секции `appId` отвергнута парсером до выполнения; исправлена секция
конфигурации. Все сохранённые YAML содержат её.

Один inline-run с отменой исправления и прокруткой к удалению выполнялся
несколько минут, но вернул `success: true` и 13 выполненных команд.
Последующая иерархия показала подтверждение удаления ниже viewport;
прокрутка к «Да, удалить» и удаление прошли. Не потребовалось менять
продукт, ослаблять проверки или очищать данные. Временный MCP остановлен
после завершения команд; эмулятор оставлен включённым.

Полный YAML запускается после интерактивной подготовки отдельным локальным
Maestro CLI, чтобы журнал шагов сохранялся независимо от MCP transport:

```sh
JAVA_HOME=/Users/gamkrelidzetimur/.sdkman/candidates/java/current \
  /opt/homebrew/bin/maestro test --device emulator-5554 --no-ansi \
  --debug-output test-results/mobile/ux-improvements/full-debug \
  --test-output-dir test-results/mobile/ux-improvements/full-run \
  --format JUNIT --output test-results/mobile/ux-improvements/full-report.xml \
  tests/mobile/demo/ux-improvements.yaml
```

Полный запуск **успешен**: 1/1 Flow Passed, CLI exit code 0; JUnit содержит
`tests="1" failures="0"`, `status="SUCCESS"`, время 473,671 секунды
(7 минут 54 секунды). Первый полный запуск этого YAML прошёл без изменения
сценария между стартом и завершением. Диагностические inline-команды выше
не выдаются за отдельные полные прогоны.

Отчёт: `test-results/mobile/ux-improvements/full-report.xml`. Журнал,
`commands.json`, `manifest.json` и исходные снимки:
`test-results/mobile/ux-improvements/full-run/2026-10-04_185256/ux-improvements/`.
Для удобства просмотра семь снимков полного запуска также скопированы в
`test-results/mobile/ux-improvements/full-01-budget.png` —
`full-07-restored-home.png`. Последние два визуально подтверждают
восстановленные 6 операций, 120 000 RUB доходов, 34 605 RUB расходов и
54 012 RUB доступных денег; итог бюджета 3 825 RUB проверен assertion.

Задержки воспроизвелись и в CLI: стандартный `eraseText` занимал около
76 секунд и успешно завершался. Поэтому длительное выполнение inline-run
не признано зависанием продукта или прокрутки. Скорость самого ввода
пользователем этим автоматизированным прогоном не измерялась.

## Границы

Первый вход, недельный/годовой период, больше пяти записей, подкатегории,
разделённые покупки, возвраты, валюты и точность расчёта покрываются
отдельными браузерными и модульными проверками основного агента. Этот
нативный сценарий не подтверждает iOS, TalkBack, увеличенный шрифт,
сохранение черновика после завершения процесса приложения или системную
блокировку. Существующие настройки защиты не меняются ради этого теста.
Нативное закрытие по фону не выполнялось: при открытой форме видимая
область фона находится под статусной строкой, а центр доступного
`Закрыть окно` перекрыт формой. Эта ветка проверяется в браузере; нативная
проверка не подменена координатным нажатием или вызовом обработчика.
