Дата: 04.10.2026. Роль: `maestro_planner`. Все четыре приоритетных
маршрута ниже выполнены последовательными inline-flow через локальный

  `appId: app.lad.finance`. Выбрано через `list_devices`.
- Режим **Demo**, `EXPO_PUBLIC_ENABLE_DEMO=true`,
  `EXPO_PUBLIC_RESET_ON_START=false`. Явно выбрано
  «Текущий профиль: Демо. Открыть профили» → «Открыть профиль: Демо».
- Runtime: `sys.boot_completed=1`, локальная дата **2026-10-04**,
  `Europe/Samara`; 1080 × 2400 px, 420 dpi, приблизительно 411 × 914 dp.
  Дата и параметры прочитаны с устройства, не приняты из часов компьютера.
- На основных экранах сохранён баннер приостановленной экскурсии
  «Продолжить обучение». Он сдвигает контент. По снимку истории с этим
  баннером нельзя утверждать, что первая строка целиком видна без прокрутки.
- До и после: октябрь 2026, шесть операций, доходы 120 000 ₽, расходы
  34 605 ₽; «Можно потратить» — 54 012 ₽. Личный профиль не изменялся.
- Проверки выполнялись одним владельцем устройства, без параллельного

## Сборка и восстановление среды

Прочитаны `docs/DOCKER.md`, `scripts/mobile.mjs`, `docker/android.mjs`,
`docker/android-entrypoint.sh` и `compose.yaml`. Docker 28.3.2 доступен.
На preflight запущенного устройства не было: старый Pixel_8 завис,
а новый обычный cold boot остановился на запросе crash-report consent.
Адресно завершены только подтверждённые процессы этого AVD. Без изменения
userdata устройство успешно запущено с документированными `emulator -help-all`
флагами:

```sh
emulator -avd Pixel_8 -no-snapshot-load -no-boot-anim -no-window -no-metrics -crash-report-mode never
```

Путь к бинарнику — Android SDK текущего пользователя. Постоянные настройки
AVD и другие устройства не изменялись. Журнал восстановления:
`test-results/mobile/ux-implementation/emulator-recovery.log`.
CUA-осмотр хостового окна Android Studio завис и был прерван; после этого
CUA не использовался. Нативный интерфейс Лада проверен через Maestro.

Результат: `BUILD SUCCESSFUL in 3m 15s`; установка `Success` с сохранением

## Повторяемость и тестовые данные

Все сценарии: Demo, только профиль Демо, дата устройства **04.10.2026**.
Они связаны одной собственной записью:

| Поле                     | Значение            |
| ------------------------ | ------------------- |
| Название                 | `UX-Native-Expense` |
| Тип                      | Расход              |
| Создание                 | 320,50 RUB          |
| После исправления        | 321,50 RUB          |
| Дата операции            | 03.09.2026          |
| Счёт                     | Основная карта      |
| Категория при сохранении | Другое              |

Перед повтором искать этот уникальный идентификатор во всей истории.
Если осталась запись от прерванного прогона, удалить **только её** через
«Удалить операцию» → «Да, удалить». Другие записи и профили не очищать.
В этом прогоне запись удалена в конце и отсутствие результата подтверждено.
При другой runtime-дате нужно согласованно изменить условия периода,
контрольный платёж и ожидания; не менять дату устройства ради теста.

Артефакты — `test-results/mobile/ux-implementation/`. Playwright использовал
отдельный каталог вывода и не удалял эти файлы.

## MUXI-01 — обычный расход и доступность сохранения: пройден

1. «Обзор» → «Расход» открывает «Новая операция». Тип, компактные
   «Быстрый ввод»/«Шаблоны», сумма, название, категория-select, счёт и дата
   находятся до свёрнутых дополнительных полей.
2. После MUXI-02 переименовать черновик в `UX-Native-Expense`, в поле
   «Дата операции» заменить дату вводом `03092026`; отображается `03.09.2026`.
   После переименования категория автоматически стала «Другое», что видно
   в сохранённой строке; исходное распознавание категории проверено отдельно.
3. Закрыть клавиатуру. Один короткий свайп от 83% к 66% высоты экрана
   (600 мс) делает «Добавить операцию» полностью видимой; нажать один раз.
4. MUXI-03 подтверждает одну запись и точную строку `−320,50 ₽`.

Ограничение: кнопка сохранения на первом экране Pixel_8 видна лишь частично,
а не целиком без прокрутки. На этом устройстве проверен один короткий свайп.
Это не измерение скорости ввода и не обещание одинакового числа жестов
при всех размерах экрана.

Снимки: `01-new-expense.png`, `03-ready-to-save.png`.

## MUXI-02 — быстрый ввод и проверка черновика: пройден

1. В новой форме нажать кнопку «Быстрый ввод», затем одноимённое поле.
2. Ввести `Кофе 320,50` → «Распознать запись».
3. Без ручного закрытия клавиатуры: клавиатура исчезла, быстрый ввод
   свернулся, прокрутка вернулась к началу формы. Видны сумма `320,5`,
   название `Кофе`, «Категория, Кафе и рестораны», выбранная «Основная карта»
   и дата `04.10.2026`.
4. Продолжить MUXI-01; отдельная операция «Кофе» не сохраняется.

Снимок: `02-recognized-draft.png`. Раскрытие шаблонов, сохранение шаблона,
разделение покупки и заполнение заметки этим нативным маршрутом не проверялись.

## MUXI-03 — область поиска, фильтры и исправление: пройден

1. «Операции», режим «Месяц», октябрь 2026. Фильтры исходно свёрнуты.
2. В «Поиск операций» ввести `UX-Native-Expense`, закрыть клавиатуру,
   прокрутить к результату. Показаны 0 операций, «Ничего не найдено»,
   объяснение «В выбранном месяце…» и «Искать во всей истории».
3. «Искать во всей истории» сохраняет запрос и находит ровно одну запись:
   группа «3 сентября», `UX-Native-Expense, 320,50 ₽, открыть операцию`.
   Подпись области — «За всю историю»; итог расходов округлён до 321 ₽,
   строка содержит точные `−320,50 ₽`.
4. «Фильтры» → «Расходы» → «Фильтры: 1». После сворачивания остаются
   счётчик активных условий и подпись «Расходы»; результат по-прежнему один.
5. Открыть собственную запись, заменить сумму `320,5` на `321,50`,
   закрыть клавиатуру, прокрутить до «Сохранить изменения», сохранить.
   Видны ровно одна операция и точные `−321,50 ₽`; дата осталась 03.09.2026.
6. Адресно удалить запись через «Удалить операцию» → «Да, удалить».
   По сохранённому запросу показано «Ничего не найдено».
7. «Сбросить фильтры» → «Месяц»: восстановить октябрь и исходные условия.

Снимки: `04-history-default.png`, `05-month-search-empty.png`,
`06-history-result.png`, `07-filter-collapsed.png`, `08-edited-result.png`.

## MUXI-04 — ближайшее обязательство до управления планами: пройден

1. «План» → «Платежи». Сразу под переключателем разделов виден
   «Календарь платежей» и ближайшие обязательства, включая
   «Яндекс Плюс, 12 октября, Запланирован, 449 ₽».
2. Нажать эту запись: открывается «Запланированный платёж», название,
   449 ₽, «По плану — 12 октября» и отдельная кнопка
   «Я оплатил — записать расход».
3. Не нажимать оплату/пропуск/изменение. «Закрыть» возвращает календарь;
   статус той же записи остаётся «Запланирован».
4. «Операции»: подтверждены 6 записей, доходы 120 000 ₽ и расходы 34 605 ₽.
   «Обзор»: 54 012 ₽. Само открытие события не провело расход.

Снимки: `09-payment-calendar.png`, `10-payment-open.png`,
`11-restored-history.png`, `12-restored-home.png`.

## Границы проверки и передача

После проверки открыт «Обзор», профиль Демо. Собственная тестовая запись
удалена; исходные контрольные значения восстановлены. Новая защита
несохранённого черновика не входила в объём изменения и не требовалась.

iOS, TalkBack, увеличенный системный шрифт, блокировка и перезапуск
с сохранённым черновиком этим прогоном не проверены. Отдельные чтения
`inspect_screen` занимали длительное время; одно чтение вернуло служебный
текст драйвера вместо JSON, повторное чтение прошло. Это не признано
дефектом продукта и не подменяет успешные проверки действий.

Для дальнейшего generator: этот план, `emulator-5554` / `Pixel_8`, локальный
MCP, Demo, только профиль Демо, APK и дата выше. После изменений продукта
снова полная сборка; YAML-переменные не обновляют установленный APK.
Постоянные YAML в этой задаче не добавлялись: выполнены inline-flow,
результаты и воспроизводимые условия зафиксированы здесь.
