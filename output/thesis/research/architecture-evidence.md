## Реальный поток изменения и сохранения

Для схемы потоков данных следует различить синхронную замену памяти и асинхронную запись устройства:

1. Форма держит черновик, разбирает ввод и вызывает метод `useFinanceActions`.
2. Метод вызывает чистое действие внутри `update(s => action(s, input, today))`. Например, `saveTransaction` — `src/state/finance/useFinanceActions.ts:82`; перевод с комиссией — `:84`.
3. `update` проверяет отсутствие незавершённого импорта, загрузку, текущий профиль и запрет параллельной операции; берёт **актуальный** `stateRef.current`, а не снимок на момент открытия формы (`src/state/finance/FinanceProvider.tsx:229`).
4. Действие возвращает новый FinanceState. Перед заменой вычисляются сериализованный JSON и допустимый размер (`FinanceProvider.tsx:217`). `replace` обновляет ссылку, ревизию, размер и React state (`:207`).
5. Эффект ставит пару **профиль + снимок** в очередь (`:1010`); очередь сохраняет уже выполняемую запись и последний ожидающий снимок, последовательно обработав их (`src/state/finance/saveQueue.ts:1`). Более старая ошибка не должна перекрывать статус новой ожидающей записи.
6. Запись выполняет `getLedgerStorage(profile).save(state)`. Только после успешного завершения конкретный объект попадает в `lastSaved` (`FinanceProvider.tsx:254`). Переключение профиля вызывает flush и проверяет сохранение точного снимка (`:518`). Ошибка сохранения видна и позволяет повторить тот же актуальный снимок (`:1046`).
7. В native: проверка финансового JSON → AES-GCM → проверка расшифрования → новый неизменяемый файл → проверка полного чтения → публикация маленького указателя → проверка указателя и файла → возможное удаление предыдущего поколения (`src/infrastructure/storage/vault.ts:380`, `src/infrastructure/storage/encryptedFileStorage.ts:153`).
8. В Web: plain ledger через AsyncStorage, без нативного шифрования (`src/infrastructure/storage/ledgerStorage.ts:6`).

Ошибка загрузки показывает восстановление и не подменяет данные пустыми (`FinanceProvider.tsx:504`). Приложение обновляет локальный день каждые 30 секунд и при возврате в active (`:1027`). Это не банковская синхронизация.

Импорт имеет отдельный протокол результата/подтверждения: CSV запускается через `commitImport`, передающий актуальный снимок и дату чистому `applyCsvImportWithSummary` (`useFinanceActions.ts:201`). Успех записи подтверждается точным повторным чтением, а не только завершением предпросмотра. При неподтверждённой записи память не откатывается молча, ID пакета сохраняются; дальнейшие финансовые изменения и смена профиля блокируются. Повтор сохранения не повторяет финансовое действие (`docs/CSV_IMPORT.md:31` и следующие абзацы).

## Модель хранения и безопасность

Не рисовать SQL-таблицы как физическую базу проекта. Предметные сущности образуют проверяемый FinanceState/JSON-агрегат; ER — логическая схема ссылок. Профиль, ключи, настройки блокировки, прогресс обучения, черновики и служебные отметки не следует смешивать с одним финансовым JSON.

| Данные                           | Native                                                                     | Web                                     | Основание                                                                |
| -------------------------------- | -------------------------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------ |
| Финансовый снимок профиля        | AES-256-GCM; отдельный файл поколения, малый указатель в AsyncStorage      | Открытое браузерное локальное хранилище | `ledgerStorage.native.ts:18`; `ledgerStorage.ts:6`; `docs/SECURITY.md:5` |
| Ключ финансового профиля         | Отдельно SecureStore; iOS WHEN_UNLOCKED_THIS_DEVICE_ONLY                   | Нет нативного ключа                     | `ledgerStorage.native.ts:19`, `:42`                                      |
| Реестр и имена профилей          | Открытые служебные записи AsyncStorage                                     | Открытые служебные записи               | `docs/SECURITY.md:15`                                                    |
| Черновики операции/первого входа | Отдельный AES-GCM ключ профиля                                             | Открытый JSON                           | `docs/SECURITY.md:85`                                                    |
| Прогресс обучения                | Отдельные несекретные метаданные                                           | Аналогично                              | `docs/SECURITY.md:19`                                                    |
| Полный экспорт JSON / .ladrescue | Открытый файл                                                              | Открытый файл                           | `docs/SECURITY.md:37`                                                    |
| .ladbackup                       | Отдельный пароль и отдельное шифрование; ключ устройства не экспортируется | Совместимый формат на WebCrypto         | `docs/SECURITY.md:41`; `passwordBackup.ts:32`                            |

Нативный адаптер шифрует через Expo Crypto и хранит секрет SecureStore; при дешифровании преобразует base64 в bytes для Android SDK 57 (`src/infrastructure/storage/ledgerStorage.native.ts:53`). Имена ключей и сервисы разделены по профилям. Повреждённое зашифрованное состояние не вызывает автоматический откат к открытой копии. При миграции открытый источник удаляется только после записи и обратной проверки (`src/infrastructure/storage/vault.ts:401`).

Файловая запись создаёт новое поколение без перезаписи старого файла. При неопределённом commit оставляет оба; неопубликованное поколение не выбирается автоматически как «самое новое». Проверка чтением подтверждает видимость записи в работающей ОС, но не физический fsync/сохранность при обесточивании (`encryptedFileStorage.ts:181`, `docs/SECURITY.md:9`).

Парольная копия: PBKDF2-HMAC-SHA256, 600 000 итераций, ключ 32 байта, соль 16 байт, nonce 12 байт, тег 16 байт; параметры фиксированы и проверяются до дорогого KDF (`src/infrastructure/crypto/passwordBackup.ts:9`, `:48`, `:88`; `docs/SECURITY.md:41`). Native использует Expo Crypto и noble-hashes KDF, Web — WebCrypto (`backupCrypto.native.ts:11`, `backupCrypto.ts:5`). Пароль не сохраняется, ключ устройства не экспортируется; рабочие массивы обнуляются, но гарантировать стирание JavaScript-строк/всех копий ОС нельзя (`passwordBackup.ts:111`; `docs/SECURITY.md:67`). Это описание реализованной защиты, не заключение независимого аудита.

Блокировка использует биометрию либо допустимый системный код; на Android запрос strong biometrics; включение/выключение требует аутентификации (`src/infrastructure/device/deviceSecurity.native.ts:25`). Android — запрет захвата через Expo ScreenCapture, iOS — защита app switcher (`:47`). Потеря активности блокирует интерфейс; background во время аутентификации не даёт открыть его (`SecurityProvider.tsx:52`). Черновик формы остаётся в дереве; оболочка скрывает финансовый интерфейс и доступность под блокировкой (`AppShell.tsx:122`).

Ключ не требует аутентификации на каждый доступ (`requireAuthentication` не используется); блокировка не защищает от скомпрометированной ОС или чтения памяти процесса. Face ID требует собственной сборки, в Expo Go не работает (`docs/SECURITY.md:33`). Web-адаптер системную защиту не обещает (`deviceSecurity.ts:1`).

## Файловые интерфейсы и внешние зависимости

CSV/TSV импорт: 2 000 000 байт, 5000 логических строк данных, 50 колонок; UTF-8/Windows-1251, `;`, `,`, табуляция, выбор заголовка и сопоставления полей (`docs/CSV_IMPORT.md:5`). Мастер выбирает активный повседневный счёт, показывает предпросмотр, ошибки, дубли и итоговый баланс; выбранный пакет проверяется по актуальному учёту и применяется одним обновлением. Поддержка форматов банков не объявлена сертифицированной.

CSV экспортирует выбранный период/счёт в универсальный формат либо YNAB; набор делится на допустимые части. CSV не восстанавливает все внутренние ссылки разделений/возвратов/долгов. Для полного переноса используются JSON/.ladbackup. Полные копии не сливаются; допускаются замена профиля после подтверждения либо новый профиль. Большой архив .ladrescue/.ladbackup v2 восстанавливается только в новый профиль (`docs/FEATURES_CURRENT.md:75`). Финансовый формат 8 и версия криптографического контейнера — разные версии.

Обычный финансовый JSON ограничен 5 МБ UTF-8. Большой архив — специальный маршрут совместимости допустимых старых данных с проверенным исходником и текущим снимком, не разрешение произвольного роста. Интерфейс предупреждает с 80% лимита; это не измерение быстродействия (`docs/FEATURES_CURRENT.md:77`, `:82`; `docs/DATA_PORTABILITY.md`).

Сетевой интерфейс Frankfurter запрашивает только коды валют; счета, имена и суммы в запрос не входят (`src/infrastructure/exchange-rates/exchangeRates.ts:10`). Ответ ограничен, валидируется, таймаут — 12 секунд; при отказе доступны сохранённые и ручные значения (`:52`). Провайдер отменяет устаревший запрос при смене профиля/блокировке и применяет результат только к актуальному профилю (`src/features/currencies/model/ExchangeRateProvider.tsx:32`).

Локальные напоминания: чистый расчёт `domain/reminders.ts` задаёт окно 60 календарных дней и общий лимит 60. Синхронизатор управляет чтением, отменой, планированием и итоговой сверкой через порты; только `.native.ts` вызывает Expo Notifications (`docs/ARCHITECTURE.md:66`). Состояния `ready/off/denied/unsupported/error` различают точные обязательные данные (`src/infrastructure/notifications/notifications.types.ts:3`). Web возвращает unsupported (`notifications.ts:12`). Сверка очереди не доказывает доставку ОС; фонового сервера/push нет.

## Актуальные функции для первой главы

1. Первый вход: приветствие → четыре шага настройки → предложение обучения; восстановление черновика только по выбору. Личный, дополнительные и опциональный Demo профили независимы по финансовым данным, но не по правам доступа (`docs/FEATURES_CURRENT.md:9`).
2. Счета: повседневные/накопительные/кредитные, валюта, корректировки и сверка, архивирование нулевого счёта без действующих связей; 13 валют и сохранённые/ручные курсы (`:23`).

## Незавершённая приёмка и формулировки для ВКР

`docs/tasks/2026-10-06-follow-up/README.md:44`–`:54` явно сохраняет открытые критерии. T02–T08 — blocked по оставшейся native/нагрузочной приёмке, даже когда код и браузерный этап завершены. T01 не закрывает физические/iOS проверки и точные точки отказа. T09 — done в документальном объёме интеграций.

Для научного текста корректно: «предусмотрен нативный адаптер», «реализован протокол», «в проектном отчёте от … зафиксирован …», «была выполнена браузерная проверка …», «системная доставка остаётся непроверенной». Некорректно: «обеспечена абсолютная безопасность», «гарантирована доставка», «тестирование всех платформ завершено», «выдерживает 20 000 операций без задержек» или «внедрён банковский API». Число допустимых записей — защитный лимит формата, не измеренная производительность.

Для главы 2 достаточно описать проектирование проверки и границы существующего подтверждения; полноценный отчёт испытаний относится к главе 3, если она будет заказана отдельно.
