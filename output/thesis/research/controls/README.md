# Воспроизводимые контрольные примеры главы 3

Сценарии вызывают функции проекта на синтетическом состоянии. Они не запускают приложение, не читают пользовательское хранилище и не обращаются к банковским данным. Результаты описаны в [главе 3](../../chapter-3.md) и [протоколе](../chapter3-review.md). База проверки — `96089bf`, 29 октября 2026 года, Node.js 22.21.1.

Запуск из корня проекта с установленными зависимостями:

```sh
node --import tsx output/thesis/research/controls/forecast-control.ts
node --import tsx output/thesis/research/controls/platform-control.mts > /private/tmp/lad-platform-control-result.json
```

Первый сценарий сохраняет [forecast-control-results.json](forecast-control-results.json), проверяет доступную сумму, прогноз, покупку и сценарий, а также вызывает 49 существующих helper-кейсов. Его массивы дней являются источником [графика](../../figures/chapter3-forecast-chart.png). Второй пишет JSON в stdout; зафиксированный результат — [platform-control-results.json](platform-control-results.json). Проверены профиль, аналитика возврата, состав CSV-пакета и парольный round-trip через реальную криптографию. Используемый пароль — синтетическое значение контрольного примера, не секрет пользователя. Случайные соль и nonce не фиксируются в JSON результата.

Другие контрольные примеры опираются на исполненные существующие тесты. Точные команды, ожидаемые значения и ограничения приведены в [доказательствах учёта](../chapter3-ledger-evidence.md), [прогноза](../chapter3-forecast-evidence.md) и [платформенных функций](../chapter3-platform-evidence.md). Пересечение наборов не следует считать дополнительными уникальными тестами.

Генерация Word-документов выполняется bundled Python из корня проекта:

```sh
python3 output/thesis/build-docx.py --scope chapter-3
python3 output/thesis/build-docx.py --scope chapters-1-3
```

Используйте Python окружения документов с `python-docx`, а не произвольный системный Python. Первый режим создаёт отдельную главу; второй вставляет её перед неизменённой библиографией существующих глав 1–2. Режим по умолчанию сохраняет прежнее назначение генератора и собирает только главы 1–2. Нумерация формул 3.1–3.18, рисунков 19–29 и таблицы 7 соответствует общему документу.

После `render_docx.py` структурная проверка запускается bundled Python с `pdfplumber` и Pillow:

```sh
python3 output/thesis/research/check-chapter3.py \
  --render-dir /absolute/path/to/chapter3-render \
  --combined-dir /absolute/path/to/combined-render \
  --previous-dir /absolute/path/to/chapters12-render
```

Проверка сопоставляет текст, таблицы, OMML-формулы, встроенные изображения, поля, номера и размещение подписей. PNG страниц нужно просматривать отдельно: автоматические проверки не доказывают визуальную читаемость. Поле `visual_review` в зафиксированном отчёте отражает выполненный просмотр редакции 29.10.2026 и не заменяет новый просмотр после изменения текста.
